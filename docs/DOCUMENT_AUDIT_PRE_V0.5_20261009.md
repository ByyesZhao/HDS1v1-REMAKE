以下差异已写入正文，审核时尤其注意：

1. 普通活动结束不是独立回合触发；有待看/延后检查时才利用预计结束时间安排检查。校园事件不自动转为预约任务。
2. 共同模式绕过手机门禁，仍受睡眠暂停。起床选择新轮前可以先完成到期环境更新；旧未完成轮首先按恢复阶段续办。
3. 自然语言日期由模型理解，程序接受带日期与时区的结构化时间；没有自然语言时间解析器。
4. 睡眠具体偏好覆盖相应时间，次晨共同预约再提前起床；没有冲突求解器。取消预约不会自动恢复更晚的起床时间。无效睡眠关系会抛错并暂停。
5. 概率在候选工作区逐项计算/清零，全部输出与后处理完成后才提交正式计数。`contactEligible` 标记和实际私人生活合同抽样分别判断。
6. 角色记忆使用 JS 关键词/汉字二元组匹配，不是 FTS/Embedding。30 条近期原文、七天最多 12 条短期、12 项细节、8 条长期固定在代码中；历史预算可配置；整理单独按 details/retrieved 算预算，避免未使用历史挤掉相关记忆。
7. 客观叙事、双方确认、事实变化、动作裸正文和表达忠实性由提示词要求。程序硬校验主要是结构、时间、已知任务/事件/来源 ID；新建记忆及细节变更还要求至少一个本轮来源 ID，个人导演创建/更新检查任务要求最终时间晚于本轮；没有独立事实审核或剧情矛盾检测。
8. 一次模型任务最多两次格式修补，另允许一次本地查找续调用；修补重新请求完整 JSON，不保证散文逐字不变。普通请求的 HTTP 故障直接上抛，查询续调用异常会进入同一有限修补路径；没有独立网络重试器。
9. SQLite 是 JSON 行与表达式索引，`detail_history` 独立表；完成标记在 `turns.done/completedAt`，`post_jobs` 只有整理结果。
10. 运行异常保存的暂停跨重启保留，需要 `hdsi.resume`；未暂停的意外退出才会在启动时自动恢复。冻结素材是 ID，没有冻结图片字节。
