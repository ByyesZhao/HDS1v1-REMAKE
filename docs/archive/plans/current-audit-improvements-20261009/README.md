## 2. 范围与固定决策

1. B1 修的是事件日期，不改变记录创建／更新时间、短期期限、长期保留许可的含义。无日期重谈继承既有事件范围；显式有依据的历史日期仍可并入。保持原并集规则，不引入范围缩小或自动猜测修复旧污染记录。
2. B2 的 `batchCharacters=null` 继续不限。非空时约束主选项，首项可单独超过软目标，依赖闭包保持完整。首次选择和明确未开始任务的派发刷新使用同一规则；已开始或旧未知任务按冻结输入恢复。
3. 普通段按本阶段实际可见交互排序，完整保留当前默认四段；活动全文不裁剪。不能直接以 `lastInteractionAt` 选四段，也不能用 `LIMIT` 截段内消息。
4. 基础记忆只为最终发送的 owner 资料计预算。默认不限时结果等价；有限预算时移除被丢弃的 recent／detailHistory 的预算占用，是有意修正，不宣称逐字等价。查询权限和真实来源约束保持。
5. 学校知情仍按公开版本、记录版本、获知时刻、稳定顺序选择；同次扫描中的 release 写入对后续 selection／deadline 可见。先用按需 SQL，不加持久“最新知情”投影表或跨轮缓存。
6. 查询验收区分“少解码／少传输”和“数据库不再扫描”。本批不承诺所有查询与历史规模完全无关，尤其普通窗口的合格消息聚合和同实体知情末端排序。
7. 清理只处理相关活动任务；已完成载荷即时压缩，历史残留走显式停服分批回收。覆盖维护、索引、`post_jobs`、网页 checkpoint；保留历史身份及统计。不得回退 R1 的失败、停止、重开、应用重试恢复。
8. 不增加语义裁判、在线供应商、多进程、任意上下文截断或防御性检查项目。当前 `semantic=null`、搜索未装配、真实 QQ／长期运行未验收的边界不变。
