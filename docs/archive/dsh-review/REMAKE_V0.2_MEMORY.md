# HDSI V0.2：记忆、背景与角色状态

返回 [总架构](REMAKE_V0.2.md)。生活与消息可见性见 [生活方案](REMAKE_V0.2_LIFE.md)，结构示例见 [接口文档](REMAKE_V0.2_INTERFACES.md)。

截至 2026-10-07，核心流程已实现，已有 55 项离线测试；真实 QQ 与完整故事路径尚未验收。当前九个模型任务均使用 Flash，其中八项低推理、一项高推理；表情素材描述另用高推理 Flash，合计低 8 / 高 2，各任务也支持独立配置 Pro。详细映射与验证范围见 [README](README.md)。

记忆整理属于[恢复专题](REMAKE_V0.2_RECOVERY.md)的段 B：完整结果先保存在后处理工作区，再与情绪、体力、预约等本轮故事效果一起原子提交。中断只重做或续办整理，不重新发送已经完成的回复。

程序负责记忆输出结构、来源 ID、可加强的长期记忆 ID、同轮加强去重及原子提交。事实是否已确立、偏好是否稳定、变化是否有依据由整理提示词要求模型判断，当前没有独立事实连续性审核器。

## 1. 记忆的最小结构

| 类别 | 内容 | 使用方式 |
| --- | --- | --- |
| 核心背景 | 身份、年龄、性格、关键过去、基本关系、学校与作息习惯 | 每轮作为个人导演和主叙事的背景输入 |
| 稳定细节 | 手机型号、室友姓名与籍贯、房间布置等已确立信息 | 不随时间遗忘，按主题检索 |
| 短期记忆 | 近期对话和生活事件摘要 | 检索过去七天内最近最多 12 条，受上下文预算裁剪；不自动删除记录 |
| 长期记忆 | 重要经历、反复出现的关系经验、有持续影响的事件 | 相关检索，低频淡出，允许加强 |
| 当前上下文 | 最近聊天原文、尚在进行的场景、这一轮新经历 | 直接注入当前回合，不另建“工作记忆系统” |

原始经历与消息是发生记录；短期/长期记忆是角色以后想起这些事的摘要。短期记忆淡出，不代表这段生活从未发生。

当前实现固定使用七天作为短期摘要检索窗口，暂未提供窗口配置；这是上下文筛选规则，不表示七天后从数据库删除记录，也不是心理遗忘规律。当前场景和未完成约定由生活状态持有，不因摘要离开检索窗口而消失。

## 2. 固定信息审核：把已经说定的细节留下来

### 2.1 允许自然补全

没有设定手机品牌时，提示词允许角色在回答中自然选择一个合理品牌；本轮整理模型可将已经明确陈述的事实输出为稳定细节变更，由程序提交。下次生成前检索到它，模型按提示规则继续使用同一信息；程序不按某一句发言自动提取或固定品牌。

主叙事中新出现的同学姓名、宿舍细节等也进入整理范围。整理提示词要求仅判断与提取已经确立的事实，不为了“补全背景”主动扩写一整份人物档案。

### 2.2 哪些适合固定

- 已有设定和用户明确确认的背景。
- 角色明确陈述的自身客观属性，如“我的手机是小米 14”。
- 主叙事明确确立的环境与人物细节，如室友的姓名。

整理提示词要求假设、玩笑、计划、情绪和猜测不当作客观细节保存。“想买苹果手机”不是“正在用苹果手机”。“今天很讨厌上课”不是永远厌学。程序检查来源引用属于本轮允许来源，不独立判定句子的事实性质。

偏好可以作为记忆保存，也可在反复出现后总结为较稳定的倾向，但不把一次“我喜欢蓝色”永久锁成不可改变的事实。V0.2 不再建立独立慢特征演化系统。

### 2.3 每轮整理，不随机跳过

每个运行过主叙事的生活回合都执行一次逻辑记忆整理，包括没有运行个人导演的场景检查回合。输入包括新经历、首次可见消息、延后回复重考虑的旧消息、本轮实际发送记录，以及当前文字计划和任务变更；实际发送记录包含角色文字/动作、公开旁白、共同活动标志和表情包记录。没有主叙事的环境更新或睡眠空回合不调用整理模型。整理合同同时输出短期摘要、稳定细节变更和长期记忆创建或加强。

这里的“一次”指每轮的逻辑整理；未保存完整结果就中断时，可以重试模型调用。已保存完整结果则直接复用，正式写入与回合完成标记在同一事务内，长期记忆加强次数不因恢复累加多次。具体去重以回合 ID 和结果条目 ID 为单位，不只依赖一条消息 ID。

没有新内容可以返回三个空列表；无需先跑分类模型判断是否值得审核，也不随机跳过。延后回复只保存重新考虑时间和意图，不保存待发旧稿；未命中的主动联系草稿不交给整理模型。计划与任务变更仅作为意图和安排上下文，提示词要求不据此建立已经发生的事实。

完成本轮稳定细节整理后，再组装下一轮模型上下文。“对话结束”在这里指完成一轮处理，不需要判断整场聊天何时结束。

### 2.4 事实稳定不等于永不改变

室友姓名不能第二天随便换一个；手机可以在真实发生购买、换机等故事事件后更新。更新保留变化原因和生效时间，例如“10 月 20 日换成苹果手机”，以便回答“以前用什么”。

更新后只有一个当前有效值；旧值由程序从数据库读取并写入变更历史，不要求模型复述旧值。程序同时保存新旧值、原因及本轮来源；`effectiveAt` 使用本轮处理时刻 `TurnRecord.at`，不从变更正文另行解析事件发生时间。同样的当前值不会重复写入变化历史。接口见[固定细节历史](REMAKE_V0.2_INTERFACES.md#8-记忆整理输出)。

用户明确修订角色设定也可以更新。整理提示词要求以检索到的旧细节为基准，仅在真实变化或用户明确修订时更新，无依据的不一致不覆盖。程序校验输出结构与来源 ID，但不独立判断变化是否真实，也不自动安排后续澄清；后续输出仍通过检索到的当前值和模型职责维持连续性。本版没有独立连续性审核与多轮定稿链。

## 3. 检索发生在生成之前

一次个人回合的输入包含以下内容，作为结构化输入交给模型，不规定心理处理的固定顺序：

1. 核心角色背景与当前交流模式。
2. 当前状态、情绪、体力、活动、约定与校园安排。
3. 主叙事本轮实现的新经历。
4. 与用户已看消息及当前场景有关的稳定细节和长期记忆。
5. 最近短期摘要与近期对话原文。

主叙事的初始检索查询由文字计划、当前场景、到期任务描述和有效环境事件描述组成；共同模式再加入本轮场景输入，普通模式不加入本轮新私聊正文。个人导演使用更新后的场景、新经历、新可见消息和重考虑旧消息构造查询。例如宿舍相关词可以召回室友细节，课程及考试相关词可以召回相关已有信息。

不把所有新增稳定细节全量注入，不把所有历史原文塞回提示词。当前轮的新经历直接提供，不能等到长期记忆检索时才有机会被看到。

### 当前检索实现

当前角色记忆存储在 SQLite，检索由程序加载记录后进行关键词匹配，未使用 SQLite FTS 或向量检索。查询提取英文词、数字和连续汉字的相邻二字词；稳定细节匹配 key、别名与当前值，最多取 12 项。短期摘要按七天窗口和时间取最近最多 12 项；长期摘要按内容/主题相关性、重要程度、提及次数和距最近加强的时间评分，最多取 8 项。无关键词相关性的长期记录不会仅因重要而入选。

近期原文只纳入已看输入与已发输出，取最近最多 30 条；短期摘要若来源非空且全部来源都已在这段原文中，则不重复注入。历史上下文使用可配置的 `historyBudget`，默认 8000 个可见字符，以序列化后的内容计数；超出时依次裁掉低排名长期摘要、较早短期摘要、较早原文、较早细节历史及低排名细节。本轮新经历和可见消息单独提供，不受这项历史预算裁剪。细节历史仅在查询含“以前”“之前”“旧”等历史意图词时提供。

关键词检索不能保证召回全部语义。提示词要求模型描写具体既有属性前使用已检索细节，未覆盖时可返回 `lookupDetails` 请求补查；每个模型任务最多执行一次补查，再继续生成任务结果。当前没有保证所有具体属性都逐项检索的独立审核链。表情包使用视觉描述和 Embedding 检索，与角色记忆分别处理；角色记忆尚未接入 Embedding。

## 4. 短期到长期

整理模型按本轮实际内容选择是否形成短期摘要，可以把显著重要的事件直接加入长期记忆，也可以返回空列表；日常小事的摘要随近期检索窗口淡出，原始记录仍保留。

重复出现的关系经验，或以后又真实讨论到同一重要经历，整理模型可以输出加强变更；只能引用本次检索交给整理模型的长期记忆 ID。程序每轮对同一 ID 最多加强一次，增加提及次数并更新最近加强时间。是否真实重谈由提示词要求模型判断；仅检索到记录不会自动加强。

长期记忆保存摘要、主题、来源、重要程度、提及次数、创建时间及最近加强时间。检索评分为：关键词相关性 × 重要程度系数（high 为 1.5，normal 为 1）×〔1 + 0.1 × min(mentions, 5)〕÷〔1 + 距最近加强的天数 / 90〕。淡出体现在检索权重，不设置每小时维护任务，也不定时删除或改写全部记忆。

故事安排与经历分别保存：“下周一考试”是环境安排，“今天考试失常”才是经历。经历通过 `relatedEventIds` 引用环境事件；摘要通过 `sourceIds` 引用本轮经历或消息，程序校验这些引用 ID。提示词要求延续同一次考试事实，不由多个模块各自制造矛盾版本；自然语言是否描述同一事件不由程序独立判断。

## 5. 情绪：自由名称，事件引起变化

情绪是个人导演维护的主观状态，可以同时存在多个，例如“有点委屈，但也期待晚上见面”。不规定封闭标签集合，不使用效价/唤醒度数值，也不强制强度档位。

每项情绪保存自由名称、程度描述和原因。个人导演输出本轮完整情绪列表，先供表达模型在工作区读取，段 B 提交时由程序替换正式旧列表，而不是累加数值 delta。输出 `[]` 就清空当前列表，不表示沿用旧值；要维持原状态，应输出原有完整列表。发送已经尝试后的恢复应用同一份冻结结果；未尝试发送的生成回退规则见恢复专题。

```json
[
  {"label": "失落", "degree": "明显", "reason": "今天考试发挥不理想"},
  {"label": "安心", "degree": "一点", "reason": "用户刚刚安慰了她"}
]
```

没有事件时可以维持原状态。散步、休息、与朋友谈心、睡了一觉也都是事件，可以促使情绪缓和；提示词要求变化根据经历与可见消息产生。程序不按时间或模型运行次数自动降低情绪，也不独立验证自由文本原因的心理因果。

情绪直接进入个人导演和表达模型的提示词，分别影响行为选择与具体说话方式，不通过一套“失落 → 回复长度减 30%”的规则表转译。表达模型按用户选择独立保留，不再增加情绪分类调用或语气评分调用。

## 6. 体力：一项简单身体状态

体力合同固定四档：`精力充沛 / 正常 / 疲惫 / 精疲力尽`，另附原因字符串。不加饥饿、口渴、睡眠债等多项数值体系。

主叙事按提示规则根据已经发生的身体过程更新体力，例如上课和运动后的消耗、吃饭休息后的恢复、睡眠质量的影响。程序校验体力档位并替换状态，不独立计算消耗或验证原因。个人导演读取体力决定是否愿意出门、早睡或继续聊天，不能直接修改体力；决定“想休息”本身不触发程序恢复。

情绪与体力互不替代。疲惫但兴奋、精力充沛但失落都可以存在。心理压力若确实造成睡不好等身体影响，主叙事实现该过程后再改变体力，不按“负面标签数量”扣体力。

## 7. 一轮例子

```text
学校安排：今天上午考试
主叙事：角色实际参加，答题不顺，考试结束；体力略疲惫
个人导演：失落，想取消原定逛街；告诉用户“今天考得不太好”
用户：安慰她
下一轮主叙事：仍在食堂，期间没有新的重大经历
个人导演：看到安慰，仍有些失落，但感到安心；愿意先一起吃饭
记忆整理：保存考试与安慰的摘要，重要关系体验可进入长期记忆
```

考试结果来自主叙事；失落与被安慰后的变化来自个人导演；体力来自实际身体过程；记忆整理只保存这些内容，不另改一遍结果或情绪。
