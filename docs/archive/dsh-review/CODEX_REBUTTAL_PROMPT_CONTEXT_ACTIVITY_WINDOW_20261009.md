# CODEX：REVIEW24 活动窗口增量复核回应

日期：2026-10-09。回应 [DSH_REVIEW24](DSH_REVIEW24_PROMPT_CONTEXT_ACTIVITY_WINDOW_20261009.md)。核对源码为当前 main `61db013`；该提交仅改 V0.5 文档，业务实现仍是本次 review 对象 `43213cf` 的代码。

结论：**主体审查合理，活动窗口规则无需再改；接受参数变更运维缺口、旧归属歧义检查覆盖不足和 V2 报告绑定错误。需要一份简短回应，收窄两处推断并明确修复边界。** 本文件是核对结论与后续修复建议，不代表代码已经修复。本轮不改产品代码、私有配置或正式库，不启动服务、不请求模型或连接 QQ。

## 1. 已确认的活动窗口行为继续保留

接受 §1～4 与 §5 活动窗口专项结论：普通 4 段独立索引；活动整体（含题外话、用户动作、起止标记）不占普通窗口、不刷新或保持普通段；当前活动使用冻结的完整授权原文；结束后普通聊天靠统一记忆检索，不能承诺逐字回放。关闭普通段不等于退出窗口。旧 V1 索引和冻结轮恢复路径仍有用途。

不再讨论语义分类题外话、活动结束后再等 15 分钟、强制关段或自动裁上下文。这些都有用户已确认的规则。

## 2. §5.1：缺口成立，但不能把修改元数据当作解决办法

### 2.1 已核实的调用链

- [chat-upgrade.ts](../../../src/deployment/chat-upgrade.ts)：V2 的索引参数不一致或缺元数据时 `canApply=false`。
- [index.ts](../../../src/index.ts)：启动门禁仅给通用迁移命令，未包含检查报告中的真实阻挡原因。
- [dialogue-upgrade.ts](../../../src/deployment/dialogue-upgrade.ts)：apply 先检查 `canApply`，参数不一致被拒绝；目标版本相同的合格库直接返回，也没有 V2 参数重建分支。

隔离库按 15 分钟升级 V2 后改传 30 分钟，check 失败、apply 拒绝；恢复 15 分钟后 check 通过，数据库主文件字节未变。**接受“没有合法入口应用新分段参数”的实质结论。**

### 2.2 两处措辞纠正

“改了空闲参数就再也起不来”应限定为“保持新参数时无法通过现有迁移入口恢复启动”。恢复原配置可解除这个参数阻挡；若另有一致性问题，仍需处理其报告。

“唯一出路是手工改 `chat_index_metadata`”不成立，而且不应作为指导。只改元数据会让检查宣称用了 30 分钟，但既有索引仍按 15 分钟分段；这绕过了兼容性门禁，没有完成重建。

最小诊断修复应显示：**数据库记录的参数、请求参数、具体阻挡原因、恢复原配置的临时处理方式**。纯参数差异不能继续只引导执行一个必然失败的普通 apply。

### 2.3 建议采用 A：显式参数重建入口

建议为现有迁移 CLI 增加明确的 `--rebuild-chat-index` 模式；check 只报告计划，apply 仍要求停服、备份。普通 apply 保持幂等，不因同版本参数变化悄悄改段。

后续实现需固定以下边界：

1. 只针对明确的参数变更制定 V2 重建计划；未知活动归属、缺消息、损坏关联等错误不能借重建标记一并跳过。元数据缺失也不等同于已证实的参数变化。
2. 为避免在途轮的保持绑定和冻结权限发生变化，首版要求没有未完成故事轮、没有进行中的共同活动。有在途时显示身份，先恢复原参数完成原轮／活动，再停服重建；不丢轮或按新窗口重写旧模型选择。
3. 重建普通消息索引、消息的普通索引关联、活动消息的排除关系、活跃段指针和参数元数据；必须处理被替换的旧普通索引行，不能只 INSERT 新段或只改元数据。
4. 保留消息 ID、正文、时间、活动身份、已读标志、记忆、公开确认、已完成轮的冻结资料，以及旧 V1 混合索引／绑定。备份后事务内重核并提交；失败回滚，提交后重新检查。
5. 同参数再次 apply 不重建；修改普通窗口段数只影响读取数量，不因它变化重建按时间划分的索引。

这属于已确认可配置参数的运维完善，不是用户否决的 QQ 关段／裁剪／脱困命令。B 也可实现，但 A 更明确地区分“检查已升级库”和“授权改写分段索引”，本次建议 A，无需新增产品选择。

## 3. §5.2：接受覆盖缺口，收窄“V1 永远不触发”

标准 V1 运行路径 [episodes.ts](../../../src/dialogue/episodes.ts) 写确认的 `startedAt/endedAt`，没有既有证据时 `evidenceFrom/evidenceTo` 为 null。现有升级歧义守卫只读后者，所以此来源的起止区间没有参与未知归属检测。隔离复现：活动 00:05～00:20，00:10 的消息缺 `sharedActivityId`，V1→V2 的报告仍 `canApply=true`、无歧义。**这是可复现的升级检查缺口。**

不过“不曾写 evidence”不能推广为全部 V1 来源：旧无版本库升级到 V1 时，[dialogue-upgrade.ts](../../../src/deployment/dialogue-upgrade.ts) 会保留推断证据跨度；`recordActivity` 也会保留已有 evidence。同一夹具补入证据跨度后，现有守卫会报告未知归属并拒绝升级。因此不是无条件死代码，而是**覆盖不了只有确认起止的 V1 来源**。

还需区分：

- 明确活动 ID：结合既有 turn／出站证据核对；冲突报告，不根据时间覆盖。
- `sharedActivityId:null`：正常 V1 输入路径明确写出的非活动归属，不等于字段缺失。没有相反的可靠消息／轮证据时，不因它落在活动时间内而改成活动消息。
- 字段缺失、且没有可靠轮证据：才是本项的未知归属。落在可靠确认起止区间或既有证据跨度内，报告具体消息与活动，不自动回填成活动或普通历史。

建议补齐上述检测而非取消细化 §13.9 的保证。已结束活动可用确认起止；活跃活动用已确认开始及当前有效证据边界；推断 evidence 与精确起止保持区分。范围不足但涉及当前活动／在途时仍报告阻挡，不编造结束时刻。

正常 V1 记录已有明确归属时无需新增分类逻辑。隔离缺失夹具不证明正式库存在错误消息，本轮没有检查正式库。

## 4. §5.3：逐项处理

| 意见 | 核对结果与建议 |
| --- | --- |
| V2 re-check 仍报告旧 `dialogueBinding` | 成立。隔离库内 V2 轮 `chatBinding.holdReply=true`，报告却是旧绑定的 null／false；check 仍合格。按轮的 `dialogueWindowVersion` 选择报告绑定，V2 读 chatBinding，旧缺失／V1 读 dialogueBinding；V2 库也可有旧恢复轮，不能只按数据库版本统一选择。可给报告增加绑定类型，保持旧字段兼容。 |
| 默认 15 与初始化配置不一致 | 有条件成立。首次从不存在的数据库正常装配时，fresh 且空表会写实际配置；并非所有非默认新库都失败。但**已经预建的空 V2 库**也会先被启动门禁拦住，不只“有消息无 character”。已用隔离空库确认 30 分钟 check 被挡。真正首次初始化应先使用实际参数；已有库即使无 character，也不能凭它当新库覆盖索引，走显式检查／重建。 |
| 删除空段会改已完成轮 chatBinding | 成立，但不是当前窗口行为缺陷。清理需释放有效在途绑定；已完成轮不再参与保持，建议保留其历史绑定，停止无必要的追写，不因此留下空普通段。 |
| `contextRefs` 缺说明 | 成立，低成本可补。说明 `lookupResult.contextRefs` 的路径引用本次 envelope 中已有 `input.context` 内容，属于复用资料，不是缺正文或新来源；不取消现有精确相等去重。已有测试覆盖正文一次及不同版本保留，尚无提示说明断言。 |
| 冻结活动消息消失／身份变化会抛错 | 行为确认，但**不能据此判为应该继续运行**。缺少被冻结资料或身份变更时，阻止本轮是必要的；正常门禁已有消息存在／活动身份检查。生成期间再次抛错属于一致性保护，app 会保存失败、暂停，不静默换资料。可以补可识别的安全原因与回归测试，不降为警告、不丢 ID、不重新扩大冻结集合。 |
| 历史告警证明偏保守 | 接受观察，不改规则。细化 §13.7 已要求“每个阶段足够数量的更新合资格普通段”；无法证明不影响就阻挡。告警少不等于实现错误，也不应为了让告警更常见而放宽保护。 |

## 5. 后续修复顺序与验收边界

建议顺序：

1. 为参数变更、V1 确认区间内未知归属、混合版本在途报告先补失败回归。
2. 接入真实启动诊断与显式 V2 参数重建，验证停服／备份、在途拒绝、替换旧行、事务回滚、同参数幂等，以及恢复原参数可继续原轮。
3. 补 V1 归属检测：缺失字段应报、明确 null 不凭时间改写、已有推断证据仍有效、跨活动冲突阻挡。
4. 修报告按轮选择绑定、首次初始化参数；合并完成轮历史绑定保留、`contextRefs` 说明等小项。
5. 补冻结消息损坏时“报错、暂停、保留原轮”的回归；不改保守历史告警门禁。同步现有细化／计划、增量交付日志及 V0.5 对应说明。

不需要用户再决定记忆范围、活动题外话或人工裁剪规则。本轮仅提出上述技术处理，**尚未实施**；正式库检查／重建另须在修复完成后依据实际参数和运行状态执行，不因本文件提前操作。
