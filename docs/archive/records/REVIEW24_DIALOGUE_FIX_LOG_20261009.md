## 3. 实际改动

`DialogueUpgradeParameters` 与 options 增加 `rebuildChatIndex`；CLI 显式 `--rebuild-chat-index`。报告增加记录参数、计划是否重建、逐轮绑定版本。纯参数差异的启动／apply提示由同一函数给出。

V2新参数重建先以记录参数检查现有索引；缺元数据、关联损坏、未完成轮或活动进行中不能借重建绕过。只读check制定计划；停服apply备份DB及已有WAL／SHM，事务内重核，替换普通索引及指针／消息关联／元数据，提交后复查。同参数幂等，普通apply不暗中重建。

新索引依原始消息时间与原回复关联生成；合并之后仍用**原索引关系**证明延迟回复所属，不读取正在改写的候选关系。消息正文／来源／活动身份／时间／已读、完成轮、记忆与V1资料不改。完成轮历史绑定可以指向已替换的历史索引身份，仍保留原始记录，不冒充当前在途绑定。

V1未知字段的检查兼容确认起止与已有推断跨度；显式null不凭时间改写，显式归属与可靠轮证据矛盾时报错。V2报告按**每个轮自身**窗口版本选绑定，混合旧恢复轮仍报告旧绑定。

首次创建Storage就使用实际分段参数；已有库无character不等同新库。清空普通段只释放未完成绑定，完成轮不追写。补查真正产生contextRefs时才附引用说明；不同版本正文继续保留。冻结活动资料缺失／身份变化仍失败暂停、保留原选择，用户安全通知有具体类型而不带消息正文或ID。

保守历史警告门禁不变；没有新增运行中关段、自动裁剪或自动修复损坏资料的功能。
