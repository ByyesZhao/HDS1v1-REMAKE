## 4. 非阻断记录与收益边界

**N1：相关知识历史的内部工作量未纳入原性能结果。** [check-scheduling-queries.cjs](../../../../scripts/check-scheduling-queries.cjs:63) 的 relatedKnowledge 样本记录返回量和 SQL 计划，未记录获知时间函数调用量或同口径计时。少量返回行并不能证明数据库内部固定成本。

本次补验：固定一个相关实体及获胜知识，追加 H=0／1,000／5,000 条旧知识时，每次返回仍为一份快照，`hdsi_epoch_ms` 分别执行 **1／1,001／5,001 次**。见 [summary.json](summary.json)。这与方案明确允许的同实体末端排序成本相符，没有发现结果错误，也不违背交付对剩余成本的文字说明。建议以后维护原探针时补入该计数，**不列为进入 E 的前置**。

普通窗口也仍有历史标量聚合成本。本次确定的收益是取消全历史正文 JavaScript 解码／排序，并按完整窗口加载正文。消费门禁有额外固定工作集读取，因此 164 条消息＋4 段不代表整个 recent 调用只有 168 次 JSON 解码；本次已将门禁开销单独列出，不能用窗口子查询计数替代全链路成本。

T1／T2 的现有测试有些断言未逐项复刻计划清单，本次针对截止组合、冻结字段和依赖真实应用补验没有暴露回归。无须仅为清单形式一致而扩大本批修复范围。
