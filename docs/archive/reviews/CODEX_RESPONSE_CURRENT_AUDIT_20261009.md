## 3. 请ASTRA在实施细化／执行计划中固定的边界

### 3.1 日期事实与记录时间

区分事件发生范围、记录创建／更新时刻、短期截止和长期保留许可。引用既有canonical事件且省略日期时，不得用整理时刻补入事件范围；记录时刻仍可为本轮时刻。真实新进展、只给一个日期、显式补充旧事件时间、引用learned／合并身份的分支要分别写清并回归。

不能简单规定 `hasNewEventProgress=false` 时忽略所有显式日期：重谈也可能补充有依据的历史日期。显式纠正是否替换／缩小旧范围需与现有合同核对，不把修复默认值变成新的全局历史改写机制。既有污染记录不能凭当前时间或最后更新时间猜测修复；若需旧数据修正，应另列有依据的处理办法。本批验收至少覆盖基础解析→生命周期→检索／模型投影，而非只断言expiresAt。

### 3.2 字符批量是可选软目标

默认null继续不限。非空时，主选项保持FIFO、任务分类、条数目标，累计完整正文的现有字符口径；首项超目标仍可单独入选，禁止裁正文。主选确定后扩展完整依赖闭包，闭包可超过目标。

除初次增量选项，还须检查明确未开始任务派发前刷新：正文增长时如何重新选主项、释放旧版本预留、保留未选dirty及队位，不能只修初次选择后再次绕过参数。已开始／旧未知任务仍沿冻结输入恢复，不因新配置裁剪或重排；保留R1累计修补进度。测试覆盖带idle正式路径、无idle兼容路径、null、首项超目标、独立多项、依赖闭包及派发前变化。

### 3.3 读取优化必须等价

普通段按本阶段实际可见交互排序，不能直接用所有段的lastInteractionAt选最新四段；保持完整段、时间及同时间稳定排序、活动排除、旧版本恢复与一致性消费门禁。记忆可跳过未消费的recent，免个人模型的轮只延后个人专用资料，不能跳过学校获知或正式提交。

学校先选活跃通知，再按需读取实体与已获知投影。投影保持公开版本→记录版本→获知时刻→稳定顺序；同次release后的新状态必须对selection／deadline可见，不能引入跨轮无失效机制的缓存。无需把持久“最新知识”表当成必选方案，可先比较定向查询成本和维护复杂度。

环境热查询使用当前批次轻量资料，保留时区变化／切回、跨日失效、终态身份不重开、四步依赖和ready复用。固定活跃集合增加历史量，比较读取／解码／写入次数及SQL计划，不只比较一次耗时，也不要求数据库索引内部完全不受历史量影响。

### 3.4 清理与恢复分开保护

去掉每条删除重复压缩所有done任务；历史补偿只处理确有残留载荷的行，可限定批次／一次性进度。相关任务修剪保留pending／computing／ready的引用失效与dirty释放行为，不能漏掉已清理依据并由晚到响应复活。

`compactCompletedPayloads()`还处理post_jobs与web_sessions，方案应一起覆盖其重复更新条件，不能只减少saveJob计数而留相同全历史写入。旧终态残留载荷应有明确兼容路径；历史ID／统计与恢复载荷分开，不顺手删除审核记录。继续通过R1真实失败／停止／重开／应用重试／prune终态回归。
