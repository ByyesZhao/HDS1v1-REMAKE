# 文档与证据目录原则

适用项目：HDSI-remake。生效日期：2026-10-09。[总入口](README.md) · [当前V0.5](v0.5/README.md)。

## 1. 四类资料分开

| 类别 | 唯一位置 | 状态 |
| --- | --- | --- |
| 当前规则 | `docs/v0.5/architecture/`、`subsystems/`、`reference/` | 与当前代码对应，不累积不同版本的规则 |
| 待实施计划 | `docs/v0.5/plans/<任务>/` | 明确未实施、依据与前置；不冒充现有能力 |
| 最近交付与复核 | `docs/v0.5/records/<任务>/`、`reviews/<任务>/` | 有代码基线、日期、实际验证与边界 |
| 历史资料 | `docs/archive/`；本地数据在 `runtime/archive/` | 仅用于追溯，不作为当前运行要求 |

根目录只放项目README、启动器、代码工具配置及已有私有部署文件。不要新建零散方案、review、log或旧架构副本。依赖、生成的lib与Git内部文件不按文档清理。

## 2. 按任务收纳过程，按功能维护规则

任务目录推荐 `YYYYMMDD-主题/`。如既有目录采用 `主题-YYYYMMDD/`，继续使用它，不因命名顺序重复建立一份。

一个任务可包含：

- `README.md`：状态、基线、范围和阅读顺序；
- `PLAN.md`／必要的细化：只有需要交接的任务才建立，不要求每个小改动复制模板；
- `DELIVERY.md`／`IMPLEMENTATION_LOG.md`：最终结果与重要过程；
- `logs/`：该任务的实际执行日志；
- `evidence/`：结构化结果和独立复现材料。

后续review归对应任务，而不是再放根目录或重建DSH-review。同一任务的多轮review允许保留原文件名，但入口只指向最终结论，列明旧意见是否已关闭。

功能规则只维护在子系统说明中。总架构只写职责、规则、逻辑；源码路径、配置、未实现差异与验证边界放实现对应。人物用途映射等当前配置参考放reference，实际私有设定保持部署位置。

## 3. 状态与交接

每份计划或报告写清日期、源码／文档基线以及`未实施`、`进行中`、`已交付`、`已关闭`或`历史`状态。人设审批、数据迁移和在线验收不因代码更新自动变成重新验证。

关闭任务后：
1. 同步当前规则及实现对应；
2. 最新交付／复核保留在当前版本，入口指向其实际证据；
3. 已完成计划、早期交付、旧review、红绿日志及文档快照归档；
4. 下一批完成后，再将被替代的交付／复核移入归档，更新索引；
5. 尚未实施的独立计划继续放plans，不能随已完成母任务一起宣布完成。

原始失败、通过结果、耗时和原始JSON不改写成“最新结果”。目录调整只修导航，日志和完整快照保持原内容。当前说明会更新，证据只表示记录时发生了什么。

## 4. 历史与本地归档

`docs/archive/`按以下分类：`legacy-design/`（旧架构）、`topics/`（功能开发批次）、`plans/`（已完成合同）、`reviews/`、`records/`、`logs/`、`document-history/`、`dsh-review/`（封存送审副本）、`packages/`（旧打包件）。从归档README查找，不在当前目录保留多份跳转占位文件。

`runtime/archive/`是本地资料：`batches/`、`observations/`、`logs/`、`restore/`、`temporary-probes/`。可能含模拟角色文本、配置或测试库；整个目录保持Git忽略，也不随默认文档送审。完整回退备份不可拆散或仅因旧版本就删除。回退时先查归档清单确认新位置，不照抄旧日志中的原执行路径。

当前正式数据库及WAL/SHM、图库、背景、待审候选、已用标定文件和配置不参与“过期文档”删除。`references/`保留仍有来源价值的导出／参考代码；它不是运行实现。

工具若支持`--output`／`--report`，新批次明确指定输出目录；不要复用含旧日期的默认路径覆盖旧证据。未迁移的工具默认输出仍有效，事后按本原则归类；不为目录整理修改产品行为。

## 5. 删除与验证

优先归档有决策、失败复现、来源、迁移或回退价值的材料。删除仅用于可证明重复的临时副本、空目录或明确无内容／无用途的垃圾。文件名相同不代表内容重复；不要跨完整审核包、备份包抽走单个重复文件。

移动前记录来源和目标，确认目标不覆盖已有文件；移动后：

- 当前目录、待实施计划与归档索引的本地链接必须可达；
- 维护Markdown导航及目录表，日志中原执行路径保持历史含义；
- 核对产品文件、在用部署数据未改变；
- 新目录进入唯一索引；旧名称可通过迁移清单查找；
- 文档整理记录只记录本次核对，不宣称重跑了旧产品测试。

本次执行示例：[整理记录与逐项清单](v0.5/records/document-organization-20261009/README.md)。
