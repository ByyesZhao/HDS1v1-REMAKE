# HDSI V0.5：提示与上下文

日期：2026-10-09。返回[总架构](../architecture/REMAKE_V0.5.md)。本文回答哪些信息送给模型、哪些由程序先判断，以及什么程度的重复已消除。

## 1. 总原则

模型只能得到所属阶段需要且可见的信息。主流程中先补生活，再决定回应；新的私聊不得提前进入普通主叙事。模型读取历史不等于角色本轮看到新消息，角色看到也不等于必须回复。

各阶段使用各自适用的提示，模型连接按任务连接键配置；固定信息审核使用独立审核提示，复用深度整理的连接，具体名称见[实现对应§4](../reference/V0.5_IMPLEMENTATION_MAP_20261009.md#4-模型任务与强度)。程序选择阶段、模式、读取资格、工具资格、固定来源和代写分支；模型判断叙事、感受、意愿、语气与事实含义。

背景、状态、意图、原文、相关记忆、客观学校安排、已知学校版本和网页资料分开表达，避免把“拟参加”当“已参加”、把“通知已发布”当“已读”。

## 2. 阶段信息范围

| 阶段 | 主要资料 | 不直接获得／不能当新来源 |
| --- | --- | --- |
| 普通主叙事 | 核心背景、原状态／计划、已过去区间、公共环境、客观学校现场及合法通知、已看普通窗口、相关记忆 | 本轮新私聊正文 |
| 共同主叙事 | 同上＋本轮活动输入、完整授权活动原文、公开节点／纲要和冻结轮信息 | 后到未选未读、未授权新用户行为 |
| 聊天／生活个人导演 | 核心背景、新经历、当前状态、首次可见及合法复议消息、相关记忆、角色已知学校版本、任务 | 隐藏的学校新安排不因关联ID变成已知 |
| 共同个人导演 | 同上＋本场授权原文及本轮已公开剧情 | 不改已实现动作，不代替用户参与 |
| 表达 | 确定意图／草稿／动作、情绪与轻量场景、当前可见消息、相关事实、风格范例，活动中加完整授权原文 | 不重新决策，不把完整作者背景当额外角色设定来源 |
| 每轮记忆 | 本轮实际经历、首次可见输入、确认输出、合法本人查阅、相关细节／记忆，活动原文辅助 | 检索／复议／旧活动全文不能单独成为本轮新来源 |
| 世界 | 世界用途背景、公共世界设定及活动世界事件 | 普通私人聊天或整场共同原文 |
| 校园／课题组 | 所属用途背景、持续计划与事项；课题组再看已提交研究进展及校园时序 | 不预读用户私人聊天，不拿角色意图当成果 |
| 周通知 | 程序已确定的通知、时间、课次、相关事项和冲突 | 不重做日期或擅加事件 |
| 深度记忆／审核 | 选中变更及完整依赖快照、允许操作、合法历史依据 | 不凭网页扩大正式来源，不要求新聊天才能整理 |
| 表情描述 | 单张素材图及描述合同 | 不读故事私聊来编图片故事 |

不同任务对学校资料的权限不能因为本地补查而放宽。世界环境目前可直接作为公共参考，尚无完整学校式知情台账，见[导演文档](REMAKE_V0.5_DIRECTORS.md)。

## 3. 背景用途与事实

背景用途映射需先审阅批准。当前已启用映射：故事阶段保留完整核心背景，表达使用风格片段，世界／校园／课题组分别使用所属片段；不会仅因用途分开就重新发明导师或身份。后续可以修改风格及用途映射，下次启动读取。

当前映射没有迁移作者事实、不覆盖已有具体细节。未来如拆出手机、室友等作者事实，需审阅具体映射；缺少细节才可初始化，不能自动替换已有事实。

背景原文和具体细节互相支持但职责不同：核心身份保证连续，相关事实通过统一检索供使用，文字计划仍只表达意图。

## 4. 普通原文与活动原文

普通原文默认最近4个完整普通段，当前计入，普通交互空闲15分钟划段；旧版30条消息上限已移除。关闭段仍参与窗口，按本阶段实际可见普通交互选择，不用隐藏未读消息推动所有阶段排序。划段空闲时间属于持久化索引参数，改变它需停止服务、备份并显式重建，不能仅改配置重启，见[恢复§8](REMAKE_V0.5_RECOVERY.md#8-历史库与配置改变)。

活动整体不占4段、不刷新普通锚点。活动中按冻结的授权消息身份提供完整本场原文；未读消息只有被本轮选中／可见才提供。已经选择的旧消息在修补和恢复时不临时重新拼集合。

收尾轮保留所需活动原文，不因候选状态已经退出而丢失；下一普通轮只提供直接首次可见的积压输入及正常检索，不自动注入活动全文。世界／学校没有私人活动全文权限。开始下一活动不会改写旧场积压输入的身份；它们等待普通调度，不占普通四段，也不混入新场原文。

自主生活的内部经历通过记忆提取与检索进入后续上下文；只有真正发出的普通角色消息进入普通原文段，不把整段私人叙事复制成聊天。

## 5. 单一资料池与去重

一个请求内，消息、任务、记忆和网页正文按身份保存在同一资料池，当前可见、最近原文、活动原文或不同用途通过引用指向它。一个消息可以同时有多个角色，不复制正文。

消息按ID去重：同一句话的两条真实消息仍是两条。记忆按对象与文本／状态版本区分，不合并不同版本；网页按素材身份引用。相同学校或细节历史业务块在补查与初始输入间可以确定相等引用，不做“意思差不多”删减。

补查结果确实复用已有学校或细节历史块时，用路径引用指向本次初始输入，并明确告诉模型直接复用该处正文。引用不是资料缺失，也不增加新来源；内容不相同则保留补查正文。没有这类引用的请求不附加相应说明。

去重是单个请求内的资料组织，不代表不同模型阶段之间共用记忆缓存而不再发送背景／原文。修补为了纠错也会携带上次错误结果；同一信息仍可能以业务依据、草稿或剧情摘要再次出现，不能宣称所有文字零重复。

内部向量、维护排队计数、完整恢复记录、概率随机状态等不作为故事模型的一般资料。模型可见投影与正式完整状态分开；精简不改变程序保存的恢复依据。

## 6. 程序先判断的分支

| 条件 | 程序决定 | 模型仍决定 |
| --- | --- | --- |
| 处于共同活动、手机不可读或睡眠 | 本轮模式／可见资料／可运行资格 | 合理经历和主观反应 |
| 共同轮有无新用户输入 | 允许双方活动代写或禁止新增用户动作 | 活动内合理内容，不假造台词／心理 |
| 首轮、收束、最终轮 | 公开开场／收尾要求、线索约束及结束合同 | 怎样自然展开和收尾 |
| 是否有本轮公共正文 | 能否提出立即结束 | 正文是否已合理完成，不能以非空冒充含义审核 |
| 无主动联系资格 | 输出只能不联系 | 合格时是否愿意分享 |
| 无基础合格来源 | 免调用记忆、保存空变化 | 有来源时哪些值得记 |
| 无必需学校通知 | 免调用周模型，保存程序覆盖与冲突 | 有通知时写自然准确正文 |
| 无索引、空查询、语义未标定、标定签名不匹配或无兼容候选 | 跳过查询Embedding | 不让模型补检索权限 |
| 工具配额耗尽／本地补查已用 | 停止开放相应工具 | 以当前材料完成或保留未知 |
| 输出格式／时间／ID不合格 | 有限修补或报错 | 返回同任务的合法结果 |

程序不判断用户动作是否“符合性格”、通知散文是否每句精确、语气是否必然可爱，或叙事目标的全部含义。此类内容仍依赖提示和语义验收，不能用机械字符串相等伪装完整审核。

## 7. 补查、搜索与预算

同一次逻辑模型任务最多一次本地事实补查，授权范围继承原阶段；明确禁止补查的阶段不开放。表达与深度整理默认不开放本地补查。修补／工具续调用使用同一任务连接、权限和累计工具记录。

所有生成模型任务具备搜索会话接线，正式入口也已装配搜索服务和阶段会话；当前未选择供应商且开关关闭，故不向模型开放搜索工具，见[搜索文档](REMAKE_V0.5_WEB_SEARCH.md)。

没有人为输入总字数／token预算，默认没有相关记忆注入条数配额；旧版常驻800字配额已移除。这与存储池100／1000／500目标是不同机制，见[记忆§9](REMAKE_V0.5_MEMORY.md#9-容量归档与真实删除)。相关性、权限、四段窗口、活动授权及模型接口容量仍有效。真实接口报告超限时不自动删低相关历史，不新建强制关段／清空命令，保留失败原轮供人工判断。
