# HDSI V0.5：导演与环境

核对日期：2026-10-10。返回[总架构](../architecture/REMAKE_V0.5.md)。本文描述当前导演职责和环境流程，不要求另建独立进程。

## 1. 分层职责

| 层次／任务 | 负责 | 不负责 |
| --- | --- | --- |
| 世界导演 | 延续公共世界事件，粗粒度增量创建、修改或取消 | 不围绕角色每天制造事故，不更新角色状态 |
| 校园学校导演 | 持续学期框架及制度性安排 | 不把课程、通知或强制要求写成角色已参加 |
| 课题组学校导演 | 持续组内安排、模拟科研要求和后续调整 | 不执行真实实验、写真实论文或代角色答应导师 |
| 周计划学校阶段 | 展开周安排，生成需发布通知的自然正文 | 不自行改上游时刻，不代角色解决冲突 |
| 普通主叙事 | 上次已叙述时刻至本轮的经历、场景和体力 | 不预读本轮新私聊，不替角色决定新的自愿意图 |
| 共同主叙事 | 活动客观过程与公共剧情，按冻结权限实现行动 | 不编双方新台词、心理或活动外重大承诺 |
| 聊天／预约个人导演 | 主观反应、是否回应、动作、下一意图和双方约定 | 不把意图当过去事实，不抽主动联系概率 |
| 自主生活个人导演 | 内心想法、情绪、生活意图与分享意愿 | 不保证每次自主轮都联系用户 |
| 共同个人导演 | 理解已公开经历，决定角色反应、台词与后续 | 不重写本轮已公开动作，不另开活动推进计时 |

普通故事轮先调用普通主叙事，之后按角色可见消息、预约、自主生活、起床、学校实际获知等条件选择个人导演。不需要个人决定的检查可以只有叙事。表达和记忆另有任务职责，见对应子系统文档。

## 2. 每日环境链

按故事时区每天06:00依次执行世界→校园→课题组→周计划。争取07:00前完成是已确认的运行目标，代码没有07:00截止、完成判定或监控配置；迟到步骤继续在当日可用空档推进。角色起床、正常聊天和预约不等待四步全部完成。

首次建立数据库可以启动一次环境初始化；它不是每天必须等06:00才能建立第一套环境。后续每天只处理当日一批，跨日未提交的旧批停止接续，不补造漏掉每一天的新闻。

每步只有在前一步正式提交后才冻结输入。程序有一个独立环境准备槽，冻结本阶段业务只读视图与本地检索候选后后台等待模型；新聊天可正常生成、发送、提交。结果仅保存ready，由前台串行边界择机核对并提交；前台繁忙、未完成故事、输入15秒合批或暂停时等待。提交后让出调度、重查前台。模型／格式失败默认5分钟后重试同一冻结输入，程序级异常另按报错规则处理。

环境更新只提交环境资料，不推进角色生活、读消息、抽主动联系或表情概率，也不刷新自主周期和普通聊天段。

## 3. 世界导演

世界事件有自己的持续时间、状态、描述和依据。相同事件用既有身份修改或取消，避免每天重复建同一事件。可以无变化。

粗粒度公共事件包括战争、灾害、公共卫生或社会变化；这不是必填清单，也不要求每天生成灾难。角色生活仍以正常校园与日常背景为主。

网页资料只能支持其实际提供的信息；没有真实正文时明确作为虚构模拟，不自称实时联网。本地浏览器搜索支持Bing／DuckDuckGo；正式配置现已启用Bing，等待用户启动／重启后生效。模型仍按需决定查询，不是每日强制搜索一套新闻；实际取得并提供正文之前，不能宣称已经收集现实新闻，见[搜索文档](REMAKE_V0.5_WEB_SEARCH.md)。

目前世界环境会直接作为叙事及个人阶段的公共参考；没有与学校完全同等的“先发布、再读、再登记知情”专用流程。提示要求不要凭环境资料声称亲历或已知；不能据此保证每条世界事件都有独立获知记录。

## 4. 校园与课题组长期计划

校园计划承载学期范围、课程、考试、开学／学院活动、运动会、班会和假期等；课题组计划承载导师要求、研究任务、里程碑、组会、聚餐及游玩。

按已批准的角色背景延续培养阶段和身份。当前人物以科研为主，零常规课程是合法安排；不为填满课表制造课程。计划建立后每天检查增量，无变化可以返回空结果，不每天重建学期。

当前校园提示另写有“25岁在读研究生”的固定身份文字，尚未完全由背景用途映射提供。它是本地人物适配的实现限制；将来换人物或培养阶段时需一并核对提示，不能保证只换背景文件就适配新身份，见[实现对应§7](../reference/V0.5_IMPLEMENTATION_MAP_20261009.md#7-检索和服务边界)。

事项区分已下发时间与活动发生时间。时间可以是明确单次、每周重复、待定范围或截止日期。未知的时刻不猜小时提醒；已有下发不能被挪到未来而“隐身”。

“必需参加”表示机构要求，不是程序强制角色执行。角色可自行决定缺席、请假、协调或拒绝邀请；提出请假不等于已经获准。

两位上游导演各维护自己的范围。课题组可以参考校园时间和已提交研究进展，避免无依据安排；不能自行改课程。

## 5. 周展开与通知

程序根据上游计划推导具体课次、提醒时刻、覆盖版本和冲突。模型为必需通知逐条写非空自然正文，允许补充冲突说明，但不能改日期、课次身份或安排。通知对象与课次由程序固定。

检查本周安排；周五起准备下周，已经预展开的下周继续检查。稳定安排复用原身份；改期、缩短范围或取消只处理受影响部分，保留已经发生的历史。没有必需通知时不调用周模型，即使存在冲突也保留程序冲突记录。

通知包括首次下发、更正、取消、提醒与周摘要。默认策略：

| 时间类型 | 默认提醒 |
| --- | --- |
| 明确单次安排 | 提前1个本地日、提前120分钟 |
| 每周重复课次 | 提前60分钟 |
| 带明确时刻的截止 | 提前1个本地日、提前120分钟 |
| 待定或只有日期、无明确时刻的截止 | 不猜小时／具体时刻提醒 |

事项可以显式覆盖提醒策略。未保存的过时提醒不补建，当前下发／更正承担告知；已保存且仍合法的提醒允许延迟发布，取消或过期课次的无效提醒退出。个人提醒只围绕角色已经知道的安排，已读且时间明确的公开计划可推导对应课次。

个人提醒资格只读取已经获知的公开版本，不登记新知识。已读计划只有在事项身份、公开版本、对应课次及起止时刻准确匹配时，才可推导个人提醒；未读更正、取消或不匹配安排不能补足资格。实际读取／现场获知仍须按§6提交。

学校通知是角色世界里的信息，不保证另外向真实用户发送一条QQ提醒。角色知道后是否提起，由个人导演决定。

## 6. 客观安排与角色获知

信息经过不同状态：客观安排→通知发布→可交付→实际读取／现场获知→正式知识。通知发布不等于她已读，提供通知也不强制她阅读。

主叙事可以得到当前时间／现场相关的客观课次及本轮可读通知；个人导演只得到已知版本及本轮实际获知。若课表已改而更正还没读，个人导演仍持旧认知，不能从对象ID偷猜最新课表。

实际读取必须有本轮合法通知、已发布时间、当时可读状态及对应经历；现场获知必须有可感知活动及真实经历。睡眠或洗澡时不能倒填已读；轮末清醒也不能证明早先已经看过。不读通知可留待之后合法故事轮，避免立即重复唤醒循环。

获知和经历正式提交后才成为稳定角色知识；关联活动ID本身不证明获知。同一实体只在实际获知候选中按公开版本、记录版本、获知时间和稳定顺序选取；旧课次现场事实保持历史版本，但不能回退已读的新计划。本轮投影和提交后的查询使用同一规则。

## 7. 模拟研究进度

导师下发的是要求，个人导演生成的是角色打算，主叙事实现的是过去时间内的模拟过程和结果。只有真实模拟经历对应已知研究任务时，才登记进度、完成或反馈。

完成不等于导师认可，反馈需先成为经历。几分钟不能保证做完数日研究。课题组导演下一日可根据已提交进度调整任务，不能根据未来意图伪造成果。

## 8. 当前能力边界

导演输出中的结构、时间、引用和通知覆盖有程序检查；合理叙事、通知正文准确、自由意愿与身份延续主要依赖提示和真实样例验收。

世界／学校的模拟安排不等于真实学校官方事实；仅实际网页支持的部分可以标为外部引用。网页查询、回复语气和背景用途详见[搜索](REMAKE_V0.5_WEB_SEARCH.md)、[上下文](REMAKE_V0.5_CONTEXT.md)。

环境步骤每日身份与上游屏障保持；调度只读元数据。提交核对本阶段实际业务依据：group含科研progress成员与正文，week含既有安排、知情快照、预约和通知业务结构；新无关消息不使候选池整体失效。通知正常发布／已读生命周期不单独失效。同日依据改变延后5分钟重新冻结、generation递增；跨日／时区终结旧批次并取消请求，终态身份不重开。旧输入preparationVersion0继续串行恢复，新快照version1采用异步流程。
