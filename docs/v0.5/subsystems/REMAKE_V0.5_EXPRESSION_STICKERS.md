# HDSI V0.5：表达、发送与表情素材

核对日期：2026-10-13，源码基线`2eba393`。本轮[静态核对](../records/document-code-crosscheck-20261013/README.md)源码、既有测试与记录，配置值沿用[此前白名单](../records/document-current-sync-20261011/evidence/effective-models.json)，未重新读取私有配置、重跑产品测试或执行在线验收；[2026-10-11静态核对](../records/document-post-remediation-sync-20261011/README.md)保留为历史证据。返回[总架构](../architecture/REMAKE_V0.5.md)。本系统把“决定说什么”“怎样说”“是否附图”“确认发出”分开。

## 1. 意图与表达

个人导演先决定是否输出。需要输出时给想表达的意图及初稿；只有本轮按线下共同活动表达时才可附已选择动作。普通回复、线上共同反应与主动分享只输出聊天文字。沉默时不额外调用表达模型。

表达模型微调语气、口语感、句长和分段，参考已批准人物风格、聊天范例、当前情绪和场景。角色的活泼、可爱、开朗等风格来自人物设定与可修改风格映射；没有额外语气打分或审核模型。

必须保留草稿的信息、态度、否定、承诺和动作选择。确定“明天10点联系”不能改成“可以吗／尽量”，也不能为自然表达补出手机刚买、刚拿到、熟悉程度等新事实。已有草稿合适可以原样。

表达不重新决定考试结果、接受邀请或是否配合用户动作。网页即使开放也只可帮助核验／润色既定内容，不引入新故事事实。

每次个人导演生成回复草稿、以及每次表达润色，固定加入三条口语规则：回应对方的意思，省去无作用的整体评价、旁观分析和元话语；不把做事、近况或玩笑当成申请批准，仅保留有意义的赞同、接受和约定；标点、重复字、短片段和气泡自然承载节奏与感情，不机械加标点。

本轮首次可见或明确复议的用户消息含图片／表情附件时，由程序额外选入表情语境规则；不根据历史图片、角色发出的素材或文字里的“图片／表情包”关键词触发。图片和表情结合整批文字理解，不必先报“看见了”或逐项描述画面；已明确识别的doge可按玩笑／调侃理解，普通狗不能等同doge，未知画面不猜。

单独的收尾表情允许已读不回，是否仍想继续由个人导演决定；既然已决定回复，表达模型保留该决定。纯表情不强制沉默，也不强制稍后回复。查询续调用及格式修补沿用同一任务的程序分支。

## 2. 分段与动作

程序按本轮实际输出模式选定合同：线下共同活动允许文字或动作，其余只允许文字。模型不自行判定动作权限；非线下动作意图、action段或藏在文字里的完整`【动作：…】`标记均属格式错误，沿既有修补流程处理，不静默删去。短文字段通常约1～25字，但这是提示节奏建议，语义完整优先，不是程序硬截断或输入预算。

线下动作输出裸正文，由程序包装成`【动作：…】`；公共剧情另包`【…】`。不得把动作包装塞进普通文字。线下面对面说话不写成“给用户发消息”。

本轮确认进入线下活动时，开场回复使用线下合同；线下活动收尾回复仍在结束标志前使用线下合同。已尝试发送的旧冻结稿继续按原恢复合同完成，已确认消息保留；新生成及未尝试回退重算使用新合同，详见[实施记录](../records/offline-action-only-20261010/README.md)。

第一段说话／动作可以立即发送；之后按下一段可见长度决定3～10秒间隔。这里的可见长度是去除空白后的字素计数，不是字符串码元长度；达到25个字素后间隔不再增加。公共旁白和表情本身不插同样打字等待。间隔从上段实际确认时刻安排，失败恢复保留确认与后续时间。

## 3. 表情触发

仅素材启用、实际有非线下角色文字段时逐段抽样。公共旁白、动作和线下文字不算机会；线下开始／结束轮按该模式排除。沉默不会为了“5%”单独发图。

长期目标约5%指合格文字段机会的期望频率。起始概率低于5%，连续未命中后递增至最高100%，命中清零；计数在故事正式提交时保存。恢复冻结稿不重抽、不换素材。公式及常数见[实现对应§5](../reference/V0.5_IMPLEMENTATION_MAP_20261009.md#5-运行参数)。

匹配和概率不同：先抽是否附图，命中才根据文字与表情意图编码查询、选择图库最高余弦相似度项。当前没有最低匹配阈值、随机挑选或语义不佳时自动取消规则，因此有图不保证每次语境恰好。

## 4. 图库入库与向量

新图：本地图片→看图描述→描述文字Embedding→保存路径、说明和向量。描述关注画面、人物表情、动作、文字与适用语境，不编图片背后的故事。

向量是图像描述／标签的文本向量，不是直接图像特征。旧图库67张已经复用原描述、标签及1024维向量，并复制到新项目；运行不依赖旧项目。

新增图片需要显式导入，不是收到QQ图片便自动进库。PNG、JPEG、GIF、WebP可作为本地素材；当前新图视觉描述效果尚未真实在线验收，动态图不能因此宣称逐帧理解。

## 5. 配置与维护

描述模型和向量模型各自配置。前次白名单中的看图描述为Flash/high，文字Embedding为Qwen/1024维；记忆向量另有独立配置。更换模型、端点或维度需按对应索引策略处理，图库要求显式重建，不能混用旧向量。

图库重建沿用旧识别文字，无需重新识图；保存素材身份与图片路径。故事发送冻结的是素材ID，不是图片字节，恢复时素材文件和ID映射必须仍可用。

`stickers import`在网页搜索启用且provider为browser时装配独立Koishi／Puppeteer上下文，素材描述可使用原20／40工具资格；默认浏览器启动等待60000ms，页面预算仍取网页配置。关闭搜索不加载浏览器；`stickers rebuild`只需Embedding，不创建网页／视觉任务。CLI不装载故事插件或QQ适配器。结束时先释放asset owner并压缩checkpoint，排空自有页面、关闭上下文后再关数据库；启动和清理失败保留诊断并非零退出。最后清理失败不会撤销此前成功入库的素材。

这里的checkpoint压缩先归档到`model_run_records`再清空活动指针，归档失败不清空；素材描述输入仍包含`imageDataUrl`，有网页会话时其完整checkpoint归档也会保留该输入。当前图库CLI没有注入逐响应错误历史记录器，不能据此宣称它记录了每次模型失败，详见[模型参考](../reference/MODEL_CALLS_AND_WEB_OPTIONS_20261009.md#2-如何修改与续调用)。

启动预算覆盖整个上下文而非仅Puppeteer就绪；正常清理等待真实canvas页关闭后再关浏览器、最后关数据库。超时后仍在进行的底层资源获取保留独立收尾，迟到资源关闭不读写数据库。

导入／重建要停止故事，具体命令见[README](../../../README.md)。原图和描述维护是显式工具操作，不增加每日自动识图或自动再训练系统。

## 6. 确认与能力边界

消息按冻结顺序发送，得到平台确认才保存为正式公开消息。公开开场／收尾及动作也遵守确认规则；已确认项恢复时跳过，未确认项可能重试，见[恢复文档](REMAKE_V0.5_RECOVERY.md)。

用户输入接受文本与图片／表情，纯图也按原合批、读取资格及活动归属落库。可用HTTP/data源直接取图，平台file令牌通过当前QQ适配器取得可解析源；不读取任意本地路径。开启visualInput后在角色有权读取时独立观察原图，再把客观观察交给故事、表达和记忆；原图不发送给其他聊天阶段。输入后可提前下载字节，识别仍等待读取资格。已知QQ原生face可用固定名称映射，无需模型；图片缓存仅按实际字节及观察版本复用。

关闭开关阻止新图预取和新的视觉识别准备；已确认历史观察优先于该开关，延期回复和重启仍复用同一不可变观察。原pending任务仍沿冻结资产／版本恢复，必要时继续原模型调用；不能把“关闭新识别”说成“任何恢复都不调用模型”。已冻结ready／unrecognized不重判。平台取图、HTTP来源或不支持的图片字节冻结为未知，不暂停整轮；取消在资产返回或报错之后重新检查，不误存成未知。模型／格式及数据库错误保持原报错合同。语音等其他附件仍不作为故事输入。入站观察不自动导入发送图库，旧图库混合用途描述不作入站客观观察。真实视觉质量尚未在线验收。

一次观察准备持有原图资产租约，覆盖字节读取、网页工具续调用、格式修补及模型等待；同一资产的并发持有者共用一次读盘和按需生成的data URL，最后一个持有者释放才丢弃内存字节／编码。持有期间不能清退文件，成功、报错和取消都在finally释放，后续恢复重新取租约。pending即使命中观察缓存也核对冻结文件可读，但不必编码；已确认历史观察或冻结ready无需再次读原图。持久checkpoint仍只存资产引用，安全停止等待已接收的观察准备结算后才允许关闭数据库，见[W6复核](../records/comprehensive-remediation-20261011/reviews/W6.md)。

入站观察的checkpoint归档及模型错误历史保留原资产引用，已确认观察也继续保留；这不延长原图资产的清理保护期，不保证永久保留原图像素。冻结ready和已确认历史观察在原图清理后仍可读取，pending恢复仍要求冻结资产可读。

现有图库兼容与查询样例已核对，也发现赞同、问候等语境偏差；不把最高相似度规则说成零误配。离线发送验证与真实QQ长期收发验收分开记录。
