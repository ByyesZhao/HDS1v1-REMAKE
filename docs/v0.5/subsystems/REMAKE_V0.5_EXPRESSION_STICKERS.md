# HDSI V0.5：表达、发送与表情素材

日期：2026-10-09。返回[总架构](../architecture/REMAKE_V0.5.md)。本系统把“决定说什么”“怎样说”“是否附图”“确认发出”分开。

## 1. 意图与表达

个人导演先决定是否输出。需要输出时给想表达的意图、初稿及已选择动作；普通回复、共同反应与主动分享遵循同一方式。沉默时不额外调用表达模型。

表达模型微调语气、口语感、句长和分段，参考已批准人物风格、聊天范例、当前情绪和场景。角色的活泼、可爱、开朗等风格来自人物设定与可修改风格映射；没有额外语气打分或审核模型。

必须保留草稿的信息、态度、否定、承诺和动作选择。确定“明天10点联系”不能改成“可以吗／尽量”，也不能为自然表达补出手机刚买、刚拿到、熟悉程度等新事实。已有草稿合适可以原样。

表达不重新决定考试结果、接受邀请或是否配合用户动作。网页即使开放也只可帮助核验／润色既定内容，不引入新故事事实。

## 2. 分段与动作

输出依自然顺序为文字或动作。短文字段通常约1～25字，但这是提示节奏建议，语义完整优先，不是程序硬截断或输入预算。

动作输出裸正文，由程序包装成`【动作：…】`；公共剧情另包`【…】`。不得把动作包装塞进普通文字。线下面对面说话不写成“给用户发消息”。

第一段说话／动作可以立即发送；之后按下一段可见长度决定3～10秒间隔。这里的可见长度是去除空白后的字素计数，不是字符串码元长度；达到25个字素后间隔不再增加。公共旁白和表情本身不插同样打字等待。间隔从上段实际确认时刻安排，失败恢复保留确认与后续时间。

## 3. 表情触发

仅素材启用、实际有非线下角色文字段时逐段抽样。公共旁白、动作和线下文字不算机会；线下开始／结束轮按该模式排除。沉默不会为了“5%”单独发图。

长期目标约5%指合格文字段机会的期望频率。起始概率低于5%，连续未命中后递增至最高100%，命中清零；计数在故事正式提交时保存。恢复冻结稿不重抽、不换素材。公式及常数见[实现对应§5](../reference/V0.5_IMPLEMENTATION_MAP_20261009.md#5-运行参数)。

匹配和概率不同：先抽是否附图，命中才根据文字与表情意图编码查询、选择图库最高余弦相似度项。当前没有最低匹配阈值、随机挑选或语义不佳时自动取消规则，因此有图不保证每次语境恰好。

## 4. 图库入库与向量

新图：本地图片→看图描述→描述文字Embedding→保存路径、说明和向量。描述关注画面、人物表情、动作、文字与适用语境，不编图片背后的故事。

向量是图像描述／标签的文本向量，不是直接图像特征。旧图库67张已经复用原描述、标签及1024维向量，并复制到新项目；运行不依赖旧项目。

新增图片需要显式导入，不是收到QQ图片便自动进库。PNG、JPEG、GIF、WebP可作为本地素材；当前新图视觉描述效果尚未真实在线验收，动态图不能因此宣称逐帧理解。

## 5. 配置与维护

描述模型和向量模型各自配置。看图描述当前Flash/high，文字Embedding当前Qwen/1024维；记忆向量另有独立配置。更换模型、端点或维度需按对应索引策略处理，图库要求显式重建，不能混用旧向量。

图库重建沿用旧识别文字，无需重新识图；保存素材身份与图片路径。故事发送冻结的是素材ID，不是图片字节，恢复时素材文件和ID映射必须仍可用。

导入／重建要停止故事，具体命令见[README](../../../README.md)。原图和描述维护是显式工具操作，不增加每日自动识图或自动再训练系统。

## 6. 确认与能力边界

消息按冻结顺序发送，得到平台确认才保存为正式公开消息。公开开场／收尾及动作也遵守确认规则；已确认项恢复时跳过，未确认项可能重试，见[恢复文档](REMAKE_V0.5_RECOVERY.md)。

用户输入入口目前只提取文本，非文本附件不作为聊天故事内容。表情发送是图库图片，不等于模型能够读用户实时发来的图片。

现有图库兼容与查询样例已核对，也发现赞同、问候等语境偏差；不把最高相似度规则说成零误配。离线发送验证与真实QQ长期收发验收分开记录。
