## 1. 合同与有限修补

每个模型任务有对应输出结构和业务检查。控制字段、日期／时区、经历时间区间、引用对象／来源及部分公开正文要求由程序校验。

三类个人导演的新taskChanges合同只接受appointment；Schema和parse共用本次构建时克隆的pending预约权限，create/update/cancel及任务详情拒绝额外字段。check_messages／scene_step仍由程序管理；合法预约及reply=later保留。更窄的合同不保证模型绝不输出非法JSON，失败仍按有限修补和暂停处理。

单次逻辑模型任务在原调用后最多两次格式修补。修补输入包含错误说明、先前结果和同任务格式要求，重新返回完整JSON；不是只发错误字段后局部拼接，也不保证散文逐字不变。

维护任务的两次额度跨后台失败／重启累计，不随每次重试重置。已用满时，后台重试仍可发送一次带原修补材料的请求；结果合法即可完成，不合法则不再追加修补。这是格式修补次数限制，不是总HTTP请求上限；整合另有首次执行＋最多2次自动重试的周期限额，耗尽后failed并全局暂停，见§7。

本地事实补查在允许阶段最多一次；网页工具按独立20／40会话执行。工具续调用和格式修补沿用原任务模型、强度、固定权限与工具进度，不切到另一“万能修补模型”。

格式合法不等于情节合理。提示词负责不假造事实、时间合理、角色自由意愿、表达保真等；没有额外语义裁判逐句审查。

## 2. 错误类型与暂停

生成、发送或基础提取／正式提交异常保留失败阶段、任务和安全摘要，暂停故事，尽力发送系统error。错误通知不含用户正文、模型原始响应、网页正文或认证内容；详细本地错误与运行状态另有记录。

冻结活动原文中的消息缺失或活动身份改变时，保留原轮及原选择，报错暂停。不能丢掉缺失项、改成普通窗口或重新选择消息继续；安全通知说明“活动原文缺失或身份变化，保留原轮”，不暴露消息身份或正文。

接口明确报告上下文超限时标记其类型。默认不自动删低相关记忆、不缩窗口、不概括、不切模型，也没有强制关段／清空命令；解除暂停后同一负载可能再次失败。

网络／HTTP异常不是格式修补，也没有通用前台网络自动重试器。环境模型失败和索引准备失败保留局部延后重试；整合／审核默认前两次失败延后，第三次失败暂停整个HDSI。实际耗尽阈值为`memory.consolidationMaxRetries + 1`次失败；设为0时首次失败即暂停。

`hdsi.pause`阻止新轮；新轮选择及等待轮普通续办／事件接管返回后、进入故事处理前还会复查暂停。此时被阻止的任务和等待代际留待恢复，已经进入故事处理的整轮仍可完成生成、发送和后处理；输入继续保存。`hdsi.resume`显式解除暂停；若存在独立maintenancePause，先在同事务确认记录的failed job／cycle并只为它开启新周期，保留同jobId、runId和repair／工具预算，再接续旧轮。前台最近错误可更新，但不覆盖维护归属；其他failed不清零，重启不消费人工resume。`hdsi.status`展示状态，过程中可按已确认锚点幂等刷新既有共同活动调度投影，不推进剧情、不刷新自主周期或把读取时刻当新消息锚点。

暂停跨重启保留。意外退出且未暂停的故事可在下次启动自动恢复；程序主动记录的失败暂停不会被重启默默清掉。

正常卸载插件时停止新调度、清除定时器，取消后台准备并等待它与已有前台处理结束，再关闭数据库。它不自动关闭另一控制台的SnowLuma，也不保证强制终止进程时能等工作结束。被中断事项在下次启动按其保存阶段恢复；主动暂停与正常停止不是同一状态。

## 3. 故事处理阶段

| 保存进度 | 接续方式 |
| --- | --- |
| 没有候选，或已冻结但outputComplete=false且全组尚未尝试发送 | discardUnattempted更新turn.at为恢复时刻，沿当前模型合同重新生成；原选择／阶段进度按各自合同保留，旧稿及旧模型任务不直接提交 |
| 新普通轮生成中或全pending候选，输入已变／合批未满 | 清旧候选，进入持久等待；静默与可读条件满足后同ID选择最新普通内容并换代 |
| 新普通轮同输入恢复 | 保留generation和阶段身份；重新核对查看资格，不可读则等待 |
| waiting轮 | 专用调度续办，必要事件可接管同ID；聊天和check任务不捎带，完成事件后再处理 |
| 已接管事件的未尝试候选 | 保持event scope、generation及原事件任务／通知，不受新普通输入门禁影响 |
| 已有任何发送尝试 | 保留冻结候选及整组输出，继续发送 |
| 某个输出已经平台确认 | 跳过它，不再次发出；沿实际确认安排后续间隔 |
| 发送曾尝试但没有确认 | 转入重试，可能再次发送 |
| outputComplete=true，包括零输出沉默，基础记忆未完成 | 保留旧turn.at及候选，只整理／提交，不再跑主叙事或重发 |
| 提取结果已保存，正式提交未完成 | 应用原结果，失败则整体回滚，不重抽概率或重算材料 |
| 正式完成已提交 | 不重复提交状态、经历、任务、记忆或完成标记 |

普通首次冻结与首次 sending 登记均在各自同步事务内核对输入版本；发送门禁位于分段延时之后、sender调用之前，控制中断不会误记retry。无输出在冻结事务内封口，此后的新输入不推翻沉默决定。任一非pending输出或firstAttemptAt证据都锁定整组尾段；已确认分段仍不重发，未知结果仍允许重试。

所以恢复不是统一“回退上一个步骤”。重生成、冻结续发与后处理接续取决于已保存的证据。

首次retry而没有confirmed、任意sending或firstAttemptAt也属于已尝试，必须保留候选和旧turn.at；本地确认项跳过，未知发送可以重试。已尝试／输出完成的旧个人结果不送进新模型Schema重验，旧check→appointment变更仍可由通用投影提交；全pending且没有尝试的旧候选必须重生成，不能使用旧Schema豁免。已保存post.result复用，完成后不重复投影。

重生成会重新补经历和判断手机资格，个人角色可能从life变为chat。含学校通知且无replyFreshness的轮沿personal阶段键复用runId并更新taskName，原修补预算、lookup和网页进度保留，新请求使用新角色合同。repairCount=2时恢复仍可请求一次合法最终结果，再次非法则不新增修补。合法工具续接可以清理旧repair正文但不清零repairCount。普通reply键含generation与taskName，合法等待／换代仍按原规则处理，不能为了复用预算强行改阶段键。文件重开和Host暂停入口验收见[任务合同交付](../records/personal-task-contract-20261011/DELIVERY.md)。

平台已收到但本地未保存确认的窗口可能造成重复发送；这里只保证跳过本地已确认项，不宣称外部QQ绝对一次。冻结表情是素材ID，不是图片字节。

## 4. 提交边界

发送前保存候选状态、经历、个人决定、表达、任务变化、概率计数、素材和输出顺序。发送确认逐项保存，确认消息成为公开来源。

输出结束后基础提取成功保存，再将记忆、真实经历、角色状态、任务、学校获知／进度、自主周期和完成标记一起提交。事务失败不留下“一半记忆、一半新状态”；已经实际发送的内容不会回滚消失。

候选中的普通消息先不标为已看；后处理正式提交才写入已看结果。角色消息已经确认而提取失败时，用户仍能看到输出，程序暂停等待后处理恢复。

## 5. 共同活动的过渡

公开开始确认后，活动接收归属和时钟已经启用，候选角色状态可能还没提交。程序用已保存开场证据认可这个合法中间状态，允许新输入继续落在活动里；首个共同节点仍须等开场轮成功提交。没有确认或没有公开消息证据不能忽略身份冲突。

末轮表达沿用原冻结资料；公开结束确认后停止按活动路由，继续完成该轮记忆与正式提交。结束轮成功提交时，未看的活动输入才转入普通批次并重新等待普通15秒，保留活动身份，不进入普通四段；合批锚点见[共同活动§7](REMAKE_V0.5_SHARED_ACTIVITY.md#7-上下文与生活调度)。

轮数、控制请求消费、静默锚点、自主计时与任务退出随成功提交处理；失败恢复不重复推进一次。后到消息不重新加入本轮已冻结活动选择。

普通段的在途保持、窗口版本和消息归属也持久化；版本1旧轮沿原恢复合同，不能在重启临时重新拼段改变权限。

## 6. 环境步骤恢复

每日世界／学校有独立批次与四阶段依赖，新模式有独立异步准备槽。冻结业务只读视图、检索候选／普通原文和配置签名后生成，先保存ready，再在前台串行事务内核对依据与提交。后一步必须等前一步提交。

新冻结结构附带可选的语义能力字段，外层版本仍为1。能力不可用时省去向量；基础查询为空而能力可用时仍冻结向量，后续实际补查再判断是否使用。旧结构继续接受原配置摘要校验；新结构同时核对保存的索引签名和维度，所有检查先于向量转换与查询。正文、来源与使用依据仍来自冻结内容，不从实时记忆补回。默认未标定仍只使用原词法／直接键规则。

模型／格式失败默认5分钟后本步骤重试，不暂停聊天；已准备结果只提交，不重新调用模型。跨日或时区导致旧批失效，未提交响应不进入新日，不把过去日环境集中补跑。

环境程序级异常交回Host串行边界，使用最新runtime暂停并报告；晚到旧lease／旧generation回调不能覆盖状态。默认卸载／取消停止先abort环境与记忆槽，再等前台及准备Promise收尾后关闭Storage；不响应abort的自定义transport也须返回后才关闭。显式安全停止不abort正常在途请求，允许当前阶段保存ready，具体见§12。普通网络重试沿同一generation，停止重开不额外增加attempt；同日业务依据失效才递增generation。旧合同在途preparationVersion0按原合同串行接续，旧ready直接复用，不强行重新解析。

网页身份始终为step.id＋generation阶段键，业务generation数字不进入网页身份，20／40累计额度不重置。唯一模型checkpoint保存lookupRequest和lookupPending；中断查询先用原请求接续，成功结果与实际usedBasis同事务保存。重新冻结时保留已用查询权限与请求，清旧结果后在新快照重新投影，不追加第二个查询；已确认网页材料／操作保持。仅终态后释放owner并允许压缩checkpoint。

环境规划协议新库为2，现有1须显式停服备份升级。升级保留旧ready/running/已冻结pending为准备版本0，未开始pending标1；不改变前台、暂停、nextEnvironmentAt。降级必须没有新模式非终态步骤，停服、备份并用专用工具检查／降级；不能手工改版本，无法满足时回退完整升级前备份会丢失备份后进度。命令见[README](../../../README.md)。

准备版本1的committed／superseded步骤在同一步骤执行结算后保留步骤身份、时间、代际与错误记录，并以`terminalAudit`保存业务依据、输入／准备／结果指纹、必需通知身份及结果实体ID／计数，再清除`inputSnapshot`、`preparationSnapshot`、`frozenResult`。没有产生结果时摘要结果为null，不补造成功结果。正常提交时业务结果与摘要同事务落盘，失败回滚后仍可用原ready结果重试；跨日废弃的执行未结算前保留正文。版本0／缺省及非终态步骤仍保持完整恢复输入；读取终态结果的验收工具使用摘要，不能把null正文解释成待重新生成。运行时只处理已跟踪步骤，不在重启时扫描回收全部历史终态正文；旧载荷可用§7的停服回收工具处理。此变更不升环境协议版本。

终态网页收尾等待同一步骤执行及其退出清理全部结束，再释放缓存并清除owner的checkpoint，保留已确认材料、身份与计数。正常提交、跨日废弃和旧串行恢复的终态路径都遵守这一收尾；旧版本业务正文仍保留，不能把网页checkpoint回收等同于业务载荷回收。收尾失败交回Host报告并暂停，不以自动反复重试掩盖失败；停止期间同样等待结算并传播错误，见§12。

## 7. 后台记忆恢复

索引和深度整理共用一个异步准备槽，保存待办、依据快照、准备结果和逐单元进度。索引重启把中断计算恢复为待准备；整合computing无结果时按已保存attempt登记一次interrupted失败，持久去重后等待重试或进入failed。已保存结果转ready，不登记新的中断失败。缺计数字段的旧pending使用legacy基线0／0；旧computing无结果仅采用这一个实际观察到的中断执行，执行／失败为1／1，不编造更早历史。旧computing已有结果转ready，执行／失败基线0／0。已就绪结果先核对对象文本／状态版本。

依据过期的单元不覆盖新事实，重新排相关变更。应用异常回滚该事务并延后重试原ready结果；整合失败计入同一周期预算，达到配置耗尽阈值（默认第三次失败）时全局暂停，索引仍沿既有局部策略。机械清除会修剪相关后台快照／向量，避免用已经删掉的正文重新写回。

每个准备／提交／清理过程都遵守前台门禁和让位；后台已经在算时可继续收消息，但深度结果只能在空闲资格重新成立后应用。

后台任务以 startedAt 显式null区分从未开始；缺字段旧任务或已开始重试保留冻结输入。深度整理满足空闲才创建，派发前同事务刷新完整依赖闭包及精确版本预留。未开始索引按owner/签名合并最新revision，未服务队位继承，服务后新版本重新排队；每次最多清理20项旧任务后续调度，清理不计请求。

维护业务快照与模型阶段 checkpoint 分别保存。准备失败 pending 或停止 computing 时保留完整输入、修补结果／累计次数、本地补查状态、未确认工具操作及既有工具结果。压缩前读回最新持久任务：仅 ready／done 清除阶段 checkpoint，pending／computing／任务已不存在均不清除；索引路径不做此维护清理。

准备结果先落盘再清进度；应用失败沿用 ready 结果，不重新请求模型。默认取消停止后的晚到响应不推进任务；显式安全停止允许当前准备阶段保存ready，不自动执行后续阶段。整合重启按持久attempt结算中断，而不是无限把computing转pending；ready结果继续只归档／提交。清理已终结的任务不会被晚到响应复活。旧版本已清空的阶段进度不能由此补回。对应修复与真实恢复验收见[R1补验](../../archive/records/ASTRA_R1_CHECKPOINT_FIX_DELIVERY_20261009.md)。

新完成done维护任务清除其网页checkpoint前先归档；pending／computing／failed未完成现场保留，ready结构化结果继续用于应用重试。逐条删除只读取引用该owner的活动任务，晚到结果仍受墓碑与持久状态门禁约束。旧终态恢复正文可用独立载荷回收工具在停服后分批压缩：默认处理索引text/result、维护snapshot/readSet/result、已完成轮post.result及终态owner网页checkpoint；显式`--include-environment`再包含准备版本1环境终态正文和审计摘要。所有选中类别共用每批默认50行，一次默认20批；不足以完成时返回hasMore，可续跑，不删消息、身份、来源、统计或未完成恢复正文。缺失owner表无法证明终态的网页checkpoint保留；工具不会为旧库补建环境表。命令、DB/WAL/SHM完整备份与代码配套恢复见[README](../../../README.md)。

载荷回收压缩的是已终态的活动恢复载荷；网页checkpoint先写入§13的不可变历史再清空活动字段。历史中的输入及模型响应不随回收或记忆删除而消失，因此回收完成不表示整库已删除所有旧正文或保证数据库文件缩小。

旧未完成故事先恢复，后在无后台 prepare 的空档执行进程一次性记忆依据补齐；缺主事件仅报告，已开始或 ready 的后台输入不改，依赖变化由应用门禁判 stale。

## 8. 历史库与配置改变

现有库遇到需要升级的窗口／活动／环境／容量标记时，明确检查、停止服务、备份后显式升级；不隐式重新拼索引、不清空旧故事。

普通分段空闲参数变化时，报错显示记录值、请求值、真实原因及恢复原参数的临时做法；不能只提示普通升级。新参数需明确授权重建，保留原消息／记忆；未完成故事轮、进行中共同活动、元数据缺失或关联损坏仍阻挡。不能只改参数记录冒充重建。具体命令见[README](../../../README.md)。

重建先按原记录参数检查旧索引，再按新参数划段。保留已有普通回复实际生成／分段发送期间的关联，不把生成前的历史空闲一并视为保持区间。已完成轮的旧绑定作为历史记录保留，当前恢复资格按各轮自身版本判断；新库首次直接记录实际配置的空闲参数。

旧V1消息归属按明确活动ID／显式null／字段缺失区分：不凭时间跨度覆盖已经明确的归属；确认起止与推断跨度只用于报告未知归属。

回退要配套代码、数据及同次备份中的日志文件，不能把新版本库直接交给旧门禁运行。版本和命令见[实现对应](../reference/V0.5_IMPLEMENTATION_MAP_20261009.md)、[README](../../../README.md)。

有限真实故事、关闭重开库和事务注入测试不等于已经验证硬件断电、平台绝对幂等或连续数月稳定运行。

## 9. 日常一致性检查

启动、恢复、进程首次输入检查及参数变化仍完整审核；日常输入检查当前工作集，全部未完成轮、未读、当前活动全文和新引用不截断。冻结／输出／任务／记忆来源／检索消费边界同步检查；旧历史警告一旦重新引用仍阻挡。段删除、活动迁移影响普通窗口证据时回退完整审核。完整审核每表复用一次快照，热查询先SQL筛选再按epoch稳定排序；此优化不删历史，也不缩小活动全文。普通窗口查询等其他路径仍可能读取历史，不能据此声称全系统成本与历史量无关。


## 10. 图片与浏览器恢复

图片逐附件保存pending／ready／unrecognized。模型失败保留pending并报错；受控来源不可用保存unrecognized。取消在取图成功或报错之后优先检查，不存成来源不可用。本轮ready和unrecognized都不因重生成、续发或后处理重判。pending沿磁盘原assetRef及阶段身份恢复，即使新图识别开关关闭也接续原合同；原文件丢失、合同版本不支持、确认观察缺失明确报错，不下载已变化URL顶替。已确认历史观察在延期回复、重启及关闭识别时仍按原消息授权复用。字节不进入checkpoint；消息观察确认与本轮终态同事务。

原图清理与不可变观察分开；保护未看、延后检查、当前窗口／活动、未完成轮及在途资产。每单元选一个元数据候选，删除前重查引用；deleting中断后可继续清理，文件已不存在可幂等完成。旧只读库无图片表不建表。

自有弹出页与父页一同等待关闭；仅父页已关不能证明全部资源排空，未知popup关闭失败仍阻挡换代。

正常停机先停止收件、等待Host、媒体和自有浏览器资源收尾，再关库。浏览器服务失去时立即阻止旧factory并停用该实例收件；旧实例关闭完成后才接纳新服务，不同时打开两个故事实例。状态区分waiting／starting／running／stopping／failed；不能将等待服务说成已运行。静态check只读指定config/database/koishi路径，不开启浏览器或模型。

回退按[执行指南](../plans/image-input-local-search-20261009/EXECUTION_GUIDE.md)使用停服、配置／构建与一致备份；不删新表、媒体目录或原失败证据。

## 11. 普通候选换代与诊断

replyFreshness 是可选轮JSON字段，不新增SQL迁移或修改对话协议。旧轮缺字段按旧合同。输入版本与新普通消息同事务；重复平台消息、控制和共同输入不递增。进入等待释放旧普通段hold，保留原消息、附件终态及来源保护；改绑重新选择对话／活动上下文。旧经历、情绪、任务和概率不提交。

同输入重启保留业务generation及20／40额度；真实重新选择才增加generation并隔离旧查询／修补／网页材料。只压缩旧业务阶段checkpoint，不清incoming_image的原附件阶段。有效记忆与本人查阅来源只来自最终个人阶段。

replyTrace只保存选择ID、集合指纹、代际、输入版本、等待期限、阶段耗时及首次尝试时间，不复制聊天、人设、网页或提示词正文。状态显示“等待新消息合批”和当前实际调度截止。工程证据见[交付](../records/chat-reply-freshness-20261010/DELIVERY.md)。

## 12. 显式安全停止

双击stop-hdsi.cmd请求当前本机实例停止。立即禁止新输入／任务，并等前台当前整轮和世界／学校、记忆、取图在途工作完成。环境与深度维护保存当前准备结果ready即可，不在停机期间运行下一阶段或绕过原资格提交。下一次启动沿既有ready重校验、running／pending恢复规则续办；不等待静默倒计时或未来预约。

已确认发送跳过、结果未知可重试的原合同不变。停止本身不增加强制超时，任务已有的请求超时和错误处理仍生效。失败不由停止程序强杀。浏览器移除／插件卸载仍用原取消流程；Ctrl+C加exit等待钩子，但Windows首选停止文件，直接关闭窗口及硬终止不保证等完。实现及证据见[交付](../records/graceful-stop-20261010/DELIVERY.md)。

### 停止失败边界（R1）

浏览器页面仍存活且关闭失败时，错误必须传回停止入口：返回失败，不打印停止完成，也不执行成功退出。生命周期队列用于状态与日志，不能把它记录错误后的完成当作资源已关闭。失败不自动重试收尾或恢复业务；后续停止请求沿用同一失败。成功时仍等待既定在途工作和资源关闭。证据见[修复记录](../records/graceful-stop-r1-20261010/README.md)。

综合整改后的停止还会等待环境终态网页收尾，包括旧执行 finally 后登记的清理。Host 等所有前台、后台和环境工作结束后，再汇总并传播错误；一个清理失败不会使另一个仍在途清理被提前放弃。Host 已排空但报告清理错误时，运行装配继续依次停止媒体、关闭浏览器和存储，最后仍返回失败并记录具体原因；媒体或浏览器排空失败则不继续关闭存储。成功退出条件保持不变。真实装配、SQLite 写入故障及测试自建本地停止端点的证据见[W7复核](../records/comprehensive-remediation-20261011/reviews/W7.md)。

整合／audit安全停止等待当前准备排空，成功ready保存不消耗失败预算。模型／归档错误若已可靠保存为可重试状态，停止成功并保留待办；终态耗尽在排空后报告并保持暂停。计数／历史写入无法可靠完成时，Host独立保留首个storageError，即使pump已消费／报告完有限错误队列，仍等前台、环境和后台全部排空后返回该存储故障；按对象身份去重，多个错误保留AggregateError。进程内锁阻止进一步派发；即使数据库拒绝paused写入也不继续运行，需修复存储并建立新运行实例再检查。

## 13. 不可变模型错误与checkpoint取证

可写Storage增量创建model_run_records(id TEXT PRIMARY KEY, data TEXT NOT NULL)，不提升既有持久协议版本，不回填无法还原的旧历史。调用失败的逐响应留存需要向ModelClient注入ModelRunHistory；正式插件已注入，素材CLI等独立脚本未统一注入，不能据此宣称所有CLI调用都有这份历史。已接入历史的ModelClient每次调用产生独立诊断invocationId，failure ID由invocationId、响应序号与类别组成；业务runId／stageKey和修补预算仍原样接续。每份无效响应在检查repairLimit之前保存，包含耗尽预算的最后一稿；前台恢复沿同runId再失败也不会覆盖先前记录。维护执行错误另关联jobId、retryCycle与attemptId。

维护执行的不可变failure category明确区分prepare、archive、apply、timeout和interrupted。未知准备／transport异常不保留任意错误字符串，只记通用准备失败；已知安全ModelRequestError／ModelFormatError和本地归档／应用Error.message经认证字段、Bearer／Basic、常见key／token／password／secret、sk-key及URL用户信息脱敏，正文规范化并限2000字符后加短阶段前缀。不存stack、cause、任意对象属性或transport headers。这些细节仅留私有历史；job.lastError、runtime、通知和status继续使用通用安全摘要。成功重试或人工resume不会抹掉历史诊断；原ModelClient无效raw／checkpoint留存仍按既有取证合同，不宣称任意字符串都能自动识别为秘密。传输错误只保存安全分类／摘要，不包含认证头；不记录token用量或计费。

每次清活动checkpoint前，先在同一事务／SAVEPOINT中保存不可变快照，原因区分completed、superseded、cancelled和compacted；相同身份重写幂等，归档失败回滚清理与相关完成写入。WebSearchStore阶段／owner清理、MemoryStore完成写入和旧载荷SQL回收共用这个入口。ready后归档异常属于维护执行失败，保留ready结果与原checkpoint，交Host处理；重试只归档／提交，不重新调用模型。

历史保存完整输入、repair、lookup和工具结果／材料引用；网页materials、operations、本人查阅来源和图片观察记录不因归档删除。原图片资产生命周期照旧，不承诺永久保存已清理像素。success、resume、purgeOwner、载荷压缩及重启均不删除取证历史；本批没有自动过期，也不把历史自动检索到新模型上下文。恢复仍只读活动checkpoint，历史只供显式取证。

只读Storage和ModelRunHistory构造器不执行DDL；旧库缺表时显式list返回空。旧库直接尝试清checkpoint而没有历史表则失败保留现场。memory:compact-payloads的可写apply受控初始化历史表，dry-run不建表；备份先于写入。数据库、备份、历史响应与正文保持私有，不进入Git。

## 14. existingLongId与确认lookup恢复（0.5.2）

基础memory恢复先由实际初始行构建三份操作权限，只有lookupPending不为true且存在确认privateLookupResult时，才从确认行扩权。旧raw／StageModelInput的权限声明被程序累计快照覆盖，保存到当前活动checkpoint后才进入ModelClient；只更改privateLookupResult，保留其他进度与原预算。归一化保存失败保留原checkpoint并沿原失败路径暂停，不发送后续模型请求，不读取或修改不可变历史来补权。

已有post.result沿原apply直接复用，不重parse新版模型合同、不生成新结果、不重发。关联create在幂等跳过后、创建short前拒绝discarded规范目标；missing、错误类型及其别名同样不能落库。同批先前变化随事务回滚，保存结果保留。旧缺progress字段继续按原false处理；done轮不重新打开，正式旧潜在重复记忆不自动合并。详见[交付与关闭证据](../records/existing-long-reference-20261013/README.md)。
