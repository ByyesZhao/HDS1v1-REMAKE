# HDSI V0.5：记忆与固定信息

核对日期：2026-10-11。返回[总架构](../architecture/REMAKE_V0.5.md)。本版汇总记忆生命周期、容量、空闲整理与最新活动／普通上下文规则。

## 1. 信息类别

| 类别 | 内容与更新方式 |
| --- | --- |
| 作者固定背景 | 人物身份、关系和核心设定，按已批准文件读取；记忆模型不改原文 |
| 具体细节 | 手机、室友、专业等有明确键的事实，带来源与变化历史，可检索和建向量 |
| 详细短期 | 事件过程、可记细节、阶段情绪与感受，通常7天 |
| 简要长期 | 什么经历及对应感受，通常90天，支持真实重谈唤醒 |
| 常驻经历 | 经过审核值得长期保留的单一经历，保留事件依据 |
| 稳定认识 | 多个真实事件支持的较稳定结论；可被标为始终提供或按相关性检索 |
| 学校知识 | 她实际读到／现场获知的安排版本，不靠记忆TTL决定学校客观安排是否存在 |

“不太重要的固定背景”可以作为具体细节检索；但已有作者事实的拆分要经过用途映射审阅，不由模型自动迁出。当前启用的映射保留完整故事背景，尚未迁移作者事实或覆盖已有细节。

手机型号等是确定事实，不代表终生不可改变。只有新的合法来源证实真实变化或用户明确修订，基础提取才更新；冲突审核本身不自动回滚。

## 2. 每轮基础提取

输出完成后整理本轮的已发生经历、首次可见输入、实际确认输出以及合法本人网页查阅。可创建／更新多条短期、明确唤醒提供的长期、修改有依据的细节。没有新内容可以全部为空；没有任何合格来源则免调用提取模型。

每条新建／更新短期、长期唤醒、细节变更至少一个合法本轮来源。缺来源可经过原任务的有限格式修补，仍不合法就报错。历史检索、复议旧消息、未来计划、未发送草稿、没命中的主动意图，不能单独建立新事实。

角色的想法、愿望和未来安排不等于已经发生。主叙事实现的经历可以记录；共同代写只在成功公开后成为共享模拟经历，不能推导现实用户新增稳定属性。

## 3. 网页来源

只有自主生活个人导演实际取得并提供给模型的本人查阅会登记独立来源，可单独支持“查阅了解到……”类短期及有依据的感受。别人经历不能变成角色亲历。

世界、学校、主叙事、聊天／共同个人导演、表达或记忆模型搜索的网页不是这个独立本人来源。它们可辅助自身工作；若后来形成实际生活经历或公开交流，仍按正常来源提取。

仅本人网页来源不能修改私人具体细节或唤醒长期。搜索查询、标题和未成功提供的正文不算已经读过。

## 4. 短期与预备长期

详细短期默认从本次新增或真实事件进展起保留7天。更新只是重谈、改写或补摘要时，不刷新七天；有真实新进展才刷新。

基础提取在创建短期时同时建立“事件摘要＋感受摘要”的关联长期。普通重要度的摘要通常在短期退出时才进入普通长期检索，90天从该生效时刻算；高重要度可以立即生效。

所以七天后并非必定再调用一次模型“短转长”。后台可以提前精炼摘要，默认到期时已有可用摘要。真实新进展发生在预备期，可把生效时刻顺延到新的短期截止；已生效长期不因改写自动续期。

创建新的详细短期并引用已有同事件长期时，也必须明确区分真实新进展与重谈／改写。新增来源本身不代表事件有新进展；重谈／改写可以补正文和来源，但不刷新已有长期的有意义事件更新时间、预备生效时刻或初始保留许可。真实新进展才更新事件进展时间，并仅在长期仍未生效时顺延预备窗口；已生效长期的续期仍走真实唤醒规则。

事件时间与记录时间分开。引用已有事件且省略两个发生日期时，继承既有发生范围；只提供一个发生日期时，本次范围为该时点；新事件未提供日期时使用本轮时间。已有范围仍取并集，真实进展标志不会自动把重谈时间当事件时间，旧污染日期不批量猜测修复。

至少事件摘要或感受摘要有一项非空，不人为限定字数。短期到期且有可用长期摘要后，可以清除详细记忆正文及派生数据；原始消息和经历仍保留。缺摘要时先保留细节并排队修复，不直接删掉唯一依据。

## 5. 长期唤醒与常驻审核

唤醒必须是本轮真的重新谈及这个经历，并引用基础当前来源。仅检索命中、模型看过摘要或顺便复述不计唤醒。

同一规范事件在同一个上海本地日期只计一次有效唤醒，即使多条消息、多轮或多个合并前ID指向它。计数按日期，不是按消息出现次数。

- 当前有效保留窗口内累计三个尚未用于续期的有效日期，第三次的有效时刻产生新的90天保留许可；同一日期不反复用于续期。
- 总计达到30个有效日期，活跃且未归档的普通长期进入后台常驻候选。
- 常驻候选不是直接写进作者背景。审核可以继续保留普通长期，或者建立常驻经历／稳定认识。
- 稳定认识需至少两个不同规范真实事件支持；同一事件的多条短期不算多个事件。
- 仍独立归档的记忆必须先经真实重谈显式恢复活跃，再考虑晋升。后台不能凭整理时刻新开保留窗口或直接晋升独立归档记忆。

同事件身份合并有一项例外：归档的重复条目并入既有未归档同事件成员时，合并后的规范事件可继承该成员已有的真实保留资格，以及成员已有的唤醒日期和保留许可。它不是新增唤醒，也不从整理时刻重新计90天；后续按合并身份的实际资格判断常驻候选。若成员全部已归档，合并结果仍归档，沿用最早真实归档锚点，不因此延后归档清理。不能确定为同一事件则不适用此例外。

晋升后事件可成为常驻依据，不再按普通90天退出。单事件经历与多事件结论分别维护；依据更新后既保留修订依据，也允许后台指出结论需要调整。

晋升认识从初次保存起携带主事件正文依据与真实证据版本。抽象结论保持独立，词法和向量正文也包含主事件依据，使晋升后的具体经历仍有召回入口；非主证据不自动变成durable，也可退出普通当前检索；有效认识引用期间，主事件与其他evidence的规范身份及摘要受物理删除保护，即使普通保留许可已到期。认识撤回后再按原清理资格处理。启动安全空档对旧活跃认识幂等补齐依据及引用，正文变化才排新向量，不制造唤醒或续期。

## 6. 相关检索与上下文

短期、长期、具体细节和常驻内容统一按资格／相关性筛选。普通聊天不会把所有记忆一起发送，也不是固定“最近几条短期”拼接。

读取阶段和权限先决定可用候选。直接事实键／别名、词法相关以及已标定的语义相关分别参与；结果融合后才提供上下文。普通读取默认当前有效内容；回忆意图可授权查询归档，变化／历史意图可授权细节历史，本地补查不能擅自扩大权限。

没有人为总字符／token预算或默认检索注入条数上限；旧版始终提供的稳定认识800字符配额已移除。相关性筛选、有效期、权限、四段普通原文和当前活动选择仍然存在。这里的注入配额与§9的存储池容量目标不同。

记忆向量与表情向量独立配置；新事实和文本变化排队更新索引。Embedding已接入，但当前语义阈值未实际标定，纯语义召回关闭，检索使用当前词法阈值和直接键匹配。不能把“已经建向量”说成“当前每次都执行语义检索”。

相关语义已标定且签名／候选兼容时才编码查询。主动跳过条件共五种：无索引、空查询、未标定、标定签名与当前索引不匹配、无兼容候选。签名包含端点、模型、维度和索引文本模板；换模型或端点而未同步标定时，不能沿用旧阈值。远程查询超时／失败可回退词法，不阻塞到无限等待。不会悄悄把向量、维护计数和内部版本全部塞给故事模型。

当前检索在读取候选前判断前四项条件，不可用时不 JOIN 向量表、不解码向量；词法、直接键和始终提供项保持原规则。默认仍为词法阈值 fact=1、experience=1、semantic=null，有索引并不代表已启用语义检索。通用候选读取默认仍带兼容向量，索引登记则明确只读取完整正文与索引文本所需字段，不受空查询条件限制。

Q1／Q2离线评估的裁决为`keep_current`：候选未达到质量门槛，继续保持上述默认阈值，不宣称实际聊天召回已改善。Q3已交付新的盲测数据与向量采集／离线重放工具，但真实供应商采集、语义质量验证和正式启用仍未执行。离线候选不会自动写入运行标定；已使用的盲测也不能继续用于调参后再称独立验证。评估结果与后续条件见[检索评估交付](../records/comprehensive-remediation-20261011/RETRIEVAL_EVALUATION.md)。

## 7. 普通四段与活动原文

默认最近4个完整普通对话段，当前段计入。普通双方实际消息后空闲15分钟关闭，仍在途的普通回复可以保持该段。关闭仍可检索原文窗口，直到被更新普通段替代。

15分钟划段是持久化索引参数；修改时需要停服、备份并显式重建。它与§8的深度整理空闲等待分开配置，后者改变不会重新划普通聊天段。

共同活动整体不占四段：动作、题外话、公共剧情和起止标记都归活动。自主轮中未向用户公开的经历也不算聊天原文；若自主联系真的产生普通公开消息，该消息可进入普通段。

活动中提供本场完整已授权原文，冻结本轮选择；后到未选未读不能插入修补／恢复。收尾轮的表达与记忆仍得到它。活动结束后的普通轮通过正常记忆检索回忆，不自动带整场聊天。

结束时仍未读的活动消息下一普通批首次可见，可以作为新来源；它们保留活动身份，仍不进入普通四段。一场活动可以多条短期、逐轮更新，没有额外结束总结模型。

## 8. 空闲15分钟整理与固定审核

深度合并、压缩、摘要精炼、常驻评估、具体细节／稳定认识审核由变更待办驱动。最后输入、确认输出、角色故事完成或活动变化刷新深度整理的15分钟截止；等待期间新对话、`【推进】`等事件继续刷新。环境轮和后台自身应用／清理不刷新此锚点。共同活动输入会刷新深度整理锚点，但不刷新普通聊天段锚点。

共同活动中不开始／应用深度整理；普通活动处境也会阻挡资格。睡眠本身默认允许后台整理，但仍需满足其他资格。没有新待办不会每15分钟反复整理整库。

后台审核具体细节只记录矛盾报告；对稳定认识可以建议修订／撤回，不直接改作者文件或凭建议覆写事实。没有提供依据可保留。

按同一事件合并短期或长期，保留成员来源和阶段感受，不因关键词相似就合并不同经历。整理不生成新唤醒或延期。已达30次仍可继续保留，不强制晋升。

后台主选默认20条，字符软目标默认null（不限）。显式设值时按完整正文码点计数，按原顺序取前缀；首条可单独超过目标，后续不会跳过大条目改选更晚的小条目。必要依赖闭包始终完整，不受主选软目标裁切。未开始等待任务刷新时释放暂缓主项的准确版本预留，保留原队位；已开始／旧未知任务沿冻结输入恢复。

固定上海时区凌晨04:30的维护扫描登记到期／晋升待办；它是兜底扫描，不取代日常空闲增量处理。该时区与可配置故事时区的每日环境链分开。

## 9. 容量、归档与真实删除

默认目标：

| 池 | 数量／期限 | 退出方式 |
| --- | --- | --- |
| 活跃详细短期 | 100条，通常7天 | 容量提前退出或到期，已有可用长期摘要 |
| 普通长期占用 | 1000条，含尚未生效的预备摘要 | 容量退出或90天到期，成为归档 |
| 普通归档 | 500条，归档最长90天 | 超量或归档到期时清除无保护内容 |

短期容量提前退出时，可把对应预备摘要提前生效。普通长期容量退出不会删除原始消息／经历；归档仍可通过授权回忆检索，真实重谈可恢复。

活跃退出优先级为：普通重要度先于高重要度→有效唤醒更少→衰减更高→最近有意义更新更早→事件发生更早→创建更早→稳定身份。不是单凭“最老”或只看“最低唤醒”。

归档清理优先：唤醒更少→最近有意义时间更早→普通重要度→事件和创建时间。只处理超量或到期范围；活跃短期关联长期及有效常驻证据受到保护。

保护或缺摘要可以使暂时数量超过目标，状态可见；不得为凑数量破坏事实链。后台逐单元清除正文、向量、唤醒许可和派生任务残留，并修剪引用。索引准备、机械容量归一／到期清理不等待深度整理的15分钟，但仍受旧轮、输入合批、暂停和前台让位门禁。

容量归一有两条执行路径：角色故事基础提交事务处理本轮容量差额，可能一次退出多条；后台历史清理每次处理一个归一／清除单元，再让出调度重查前台。“逐单元让位”不代表基础提交也每次只能处理一条。

一次同步容量或清理调用复用同一份元数据快照；没有退出工作时不加载完整记忆正文。排序先批量读取去重后的规范长期唤醒时间，再比较预计算的时间与计数；清理截止只判断是否有工作，不为此读取唤醒或排序。实际退出或摘要修复才读取选中对象的完整正文，短期退出与预备长期生效仍作为一个原子单元。快照不跨异步等待或调度轮缓存；SQLite 的 JSON 投影仍访问原存储页，不能据此推断耗时不受正文大小影响。

作者背景、具体细节、原始消息／经历、有效常驻及证据没有被这三个池统一封顶。容量目标不等于整个数据库只能保留1600条数据，也不保证长期文件体积固定。

## 10. 后台提交与恢复

基础提取属于本轮后处理，失败会保留已发送内容并暂停故事。后台索引／深度整理有一个异步准备槽，计算结果先保存，再逐单元应用。

新输入可在后台计算期间正常落库；应用前核对依据版本，旧结果不能盖掉新进展。每个提交／清理单元后重查前台，发现新故事就先处理。后台失败局部重试，不用全局暂停代替让位。

默认查询Embedding等待1.5秒；后台准备120秒、失败5分钟后再尝试。验收工具单请求300秒与这些运行配置是不同概念。

环境冻结保存与查询无关的语义能力：未标定等不可用能力不冻结向量；能力可用但基础查询为空时仍保留向量，供之后非空补查使用。旧快照没有能力字段仍可恢复；配置签名校验通过后，按实际补查请求决定是否转换已有向量。恢复只使用冻结候选，配置变化拒绝复用，不从实时库补读正文或向量。外层快照版本与原配置摘要结构不变，见[环境步骤恢复](REMAKE_V0.5_RECOVERY.md#6-环境步骤恢复)。

维护业务输入快照与模型阶段 checkpoint 分别保存。准备失败回到 pending、停止仍为 computing 时保留完整阶段输入、修补结果／次数及工具进度；只在最新持久任务为 ready 或 done 时压缩阶段 checkpoint。结果先保存再清进度，应用失败复用 ready 结果，不重新请求模型。后台重试不会重新获得两次格式修补额度；此前版本已经清空的进度不能补回，详见[恢复§7](REMAKE_V0.5_RECOVERY.md#7-后台记忆恢复)。

后台任务以 startedAt 显式null区分从未开始；缺字段旧任务或已开始重试保留冻结输入。深度整理满足空闲才创建，派发前同事务刷新完整依赖闭包及精确版本预留。未开始索引按owner/签名合并最新revision，未服务队位继承，服务后新版本重新排队；每次最多清理20项旧任务后续调度，清理不计请求。

逐条机械清理只修剪引用该owner的活动维护任务，不反复改写全部历史终态载荷。新终态载荷在完成边界压缩；旧残留由显式停服、备份、有限批次回收工具处理，保留轻量身份、统计、网页来源及未完成恢复材料，见[恢复§7](REMAKE_V0.5_RECOVERY.md#7-后台记忆恢复)。


## 11. 用户图片来源

合法本轮图片的观察可作为对应messageId的内容来提取记忆，仍必须引用本轮合法来源。附件ID、观察ref、内容hash不是新增来源ID；历史图片只随授权原文辅助理解，不扩大新来源集合。未识别图不编造画面。incoming_image搜索不是自主生活本人查阅来源，不凭它直接造新记忆。原图库向量与入站观察独立，不因入站识别而重新编码旧素材。
