## 2. 部署与结构

当前为Koishi插件，HDSI故事处理在一个插件进程内，SnowLuma提供QQ接入；模型任务不是各自独立服务。Koishi位于`D:\HDSI-remake\runtime`，SnowLuma独立于`D:\SNOWLUMA`，两个根目录cmd由用户手动启动。

SQLite使用JSON行及部分表达式索引、事务和WAL，保存正式角色、输入／输出、故事轮、经历、任务、记忆／细节／常驻、环境／学校、网页会话和后台任务。编译结果`lib/`由现有构建生成，数据库不因文档V0.5改名或新建。

## 6. 用户概括与真实行为的差异

| 概括 | 当前实现 | 文档处理 |
| --- | --- | --- |
| 自主推进算一个导演 | 程序触发普通主叙事＋生活个人导演 | 放调度，保留两个模型职责 |
| 旁白中枢负责旁白 | 原称谓实际是调度；公共旁白来自共同主叙事 | 采用“调度中枢（原旁白中枢）” |
| 七天后才总结长期 | 每轮已经建立预备简要长期，后台可精炼 | 解释预备、生效与到期清理 |
| 固定信息一确定不能变 | 作者核心不自动改；细节可凭真实变化更新 | 区分作者背景、detail、learned和审核报告 |
| 3次／30次唤醒 | 同规范事件、同上海日期去重；30只进入审核候选 | 明写不同有效日期和三次续期组 |
| 所有个人导演网页直接记忆 | 独立self_web_read仅personal_life | 不扩大已有资格 |
