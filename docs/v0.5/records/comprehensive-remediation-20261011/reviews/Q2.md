- **Calibration isolation:** `selectLexicalCalibration` projects calibration families and their queries before validation/evaluation. Changing even a malformed holdout expected-owner label leaves thresholds and group audit unchanged. The complete dataset hash intentionally changes, preserving whole-input provenance. CLI dataset structural validation is distinct from fitting and does not feed holdout metrics into selection.
- **Candidate construction and actual metrics:** thresholds are exactly 1 plus positive `lexicalCoverage` scores from the applicable owner type in the calibration group's seeded owner closure. The content construction matches real retrieval, including learned-owner `memoryIndexText`. Each trial fixes the other lexical group at 1, with semantic null. Baseline and candidate metrics come from awaited real `evaluateRetrievalDataset`, including SQL eligibility, direct keys, ContextBuilder and unconditional learned owners; raw scores only enumerate thresholds.
- **Selection rules:** undefined precision/recall/F1 is ineligible; precision must be at least 0.95; negative-query false hits cannot exceed baseline. Eligible candidates sort by F1, precision and threshold descending. Empty or wholly ineligible candidate sets retain 1.
- **Freeze and paired evaluation:** CLI persists candidate bytes with exclusive creation, obtains and validates SHA256, then claims local holdout use before either holdout evaluation. Existing candidate input requires the exact candidate hash and matching dataset hash. Holdout must be explicitly requested alone. Baseline/candidate use fresh memory stores with identical declared seeds, original requests and unconditional injections. The paired report contains both full reports, per-query differences, hashes, chosen thresholds, differences from 1, reasons and recall gain.
- **Recommendation:** both group precisions must meet 0.95 and cannot regress from a non-null baseline precision. A null baseline precision skips only the relative precision comparison. Undefined candidate metrics, additional negative false hits, undefined gain, or total recall gain below 0.10 retain current settings. The 1e-12 comparison tolerance addresses numeric representation at the 0.10 boundary.
- **CLI and compatibility:** input/output paths are checked pairwise before dataset loading or evaluation using normalized Windows casing and existing-file device/inode identity. Candidate creation is exclusive; dataset, calibration, candidate, report and usage path collisions are rejected. Synthetic settings plus actual runtime assembly accept the existing calibration envelope and observe zero remote requests. No implementation path writes runtime defaults or private configuration.

## Local usage marker boundary

The usage marker is a conservative local claim, not a global or tamper-proof dataset registry. A failure after claim creation consumes the local holdout even if evaluation/reporting cannot finish; `started` therefore means claimed and potentially observed, not safely reusable. A successful paired report has completed evidence, while a surviving `started` record blocks retry-driven tuning. Copying/renaming the input or removing a marker must not be used to treat previously viewed families as unseen. Further parameter research requires a fresh holdout with unseen families. This limitation is correctly documented in Q2-report.md and is accepted for the local workflow.
