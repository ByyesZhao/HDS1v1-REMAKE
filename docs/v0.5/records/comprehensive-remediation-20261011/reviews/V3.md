- 未标定 build/freeze 的返回向量 BLOB 字节从 4,096,000 降至 0，provider/query=0；已标定 build 保留 4,096,000 字节、provider=1、query=1。字节口径是实际返回 BLOB 大小，不是 CPU 解码时间。memory 的实测 storagePaths 仅为 `:memory:`，modelCalls/networkRequests 均为 0；已读取的修正后探针会累计并拒绝被吞异常的网络尝试。

## 中位数、正文敏感性与结论范围

独立重算两份 Markdown 中全部 **25 对中位数及 after/before**，三位小数逐行吻合；没有 after 中位数退化。记忆 12 行、调度 6 行、图片 3 行、网页 4 行均经过原始样本核对，而非仅信 performance-validation.json 的 pass。

正文由 128 增至 4096 时，after 的长/短耗时比分别为 normalize 1.165、overflow 1.076、next_deadline 1.188、未标定 build 4.070、未标定 freeze 4.906、已标定 build 2.387。较高的 build/freeze 比值来自短正文固定向量工作被移除后，保留的正文读取/上下文构造/序列化占比升高；两个字数档各自相对 baseline 都未退化。报告说明 SQLite JSON 页读取仍受正文大小影响、可用语义路径基本持平，未把行预算说成恒定毫秒，解释适当。

网页解析量采用含正文标记的整个 JSON 的 UTF-16 code units，持久体积采用 JSON 列 UTF-8 字节，不是物理数据库文件；报告已准确说明。时间是同步/异步整体调用的本机 wall-clock，包含探针开销，不能解释为真实供应商网络延迟减少或纯 CPU 性能结论。
