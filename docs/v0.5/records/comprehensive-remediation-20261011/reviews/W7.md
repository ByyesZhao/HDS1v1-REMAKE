## Resolved finding

**P2 — surface terminal cleanup failures that arrive during Host shutdown.** `EnvironmentPreparation.scheduleTerminalFinalization` catches checkpoint-compaction failure into its private errors queue. `SerialHost.stop` marks the host stopped before awaiting `environment.stop`; subsequent onReady wakes immediately return, and stop never consumes `environment.takeError`. The result is a successful shutdown return with no onError notification or persisted lastError, although the terminal checkpoint was not reclaimed. This violates W7's observable cleanup-error contract. Complete all shutdown drains first, then deliver the failure through a caller-visible error channel. Add a fault-injected Host test proving both error visibility and no early return while another finalizer is blocked.

Independent reproduction: `.tmp/comprehensive-remediation-tests/w7-review-stop-probe.ts` starts a real SerialHost with a deferred generator, supersedes its batch, injects an SQLite checkpoint-null UPDATE failure, begins stop, then settles the old generator. Initial output:

```json
{"stopRejected":false,"onErrorCount":0,"lastError":null,"checkpointPreserved":true,"terminal":"superseded"}
```

Root and implementer were notified. The correction and independent re-review are recorded below.

## Specification and quality checks

- `ownerRunIds` projects run IDs through SQL without loading session/checkpoint bodies. `finalizeOwner` snapshots queued locks for every owner run, waits with allSettled, releases only that owner's cache, then clears non-null checkpoints. Same-owner callers share the same promise; temporary map entries are deleted on success and failure. A rejected operation does not block cleanup; checkpoint write errors reject. Materials, operations, counters, sources and other owners survive. No persistent owner tombstone is introduced.
- The active execution finally clears active and schedules terminal work through its own promise's settled continuation. That finally does not await the cleanup set. The late-provider/generator-finally regression verifies full snapshots/checkpoint remain until the actual generator finally completes, guarded late checkpoint writes fail, late pages do not increase counters, and the new batch is unchanged.
- Reconciliation observes current nonterminal batch IDs and retains prior observed IDs across scheduler-first supersession. Explicit applyReady targets are observed even after their batch has already become terminal. Successful cleanup removes IDs; errors retain them for explicit retry. No full-history terminal scan is added. Re-observation filters and the pending-errors gate prevent successful or failed finalization/onReady/reconcile wake loops.
- Normal commit, expired-ready early return, nonactive superseded owners, scheduler-first supersession and already-terminal applyReady route through cleanup. Preparation-v1 compaction retains R4a's transactional normal commit and active-ready protection. Preparation-v0 terminal/expired-before/expired-error/expired-result/normal completion paths await web finalization and retain legacy preparation payloads.
- `wait` loops over active execution and tracked finalizers, including cleanup added by finally. Temporary v1 runners drain in finally and expose queued cleanup failure. Pending/retry/stop/generation invalidation preserves checkpoint identity and bodies. Host foreground chat commits while an old provider remains blocked; successful host stop waits for terminal cleanup before the test closes storage. Shutdown error visibility is now covered by the correction below.

## Correction and independent re-review

- `SerialHost.stop` now uses allSettled across active foreground, background and environment drains, then consumes the preparation error queue. It returns the original single error or an AggregateError containing every failure. Both graceful modes have a real SQLite fault test: one owner cleanup fails while a second finalizer remains blocked; stop stays pending until that second finalizer settles. Thus error propagation cannot allow early caller-side storage close.
- `plugin-runtime.close` retains its shared closing promise and the sequential host, media, browser, storage order. Because Host.stop reports after its drains settle, a Host cleanup error is collected while safe remaining resources continue to drain. If media or browser drain fails, later steps (including Storage.close) are skipped, preserving the preexisting live-storage failure contract. Host and resource errors are retained together. Aggregate causes are logged individually before the failure is rethrown.
- Real runtime assembly tests gate generator/media/browser work, inject actual terminal checkpoint write failures, verify exact resource-release order, shared close work, successful close behavior, and storage remaining open after media/browser failures. Synthetic localhost HTTP tests cover both browser-present and browser-absent runtime assembly: the response remains 500/stopped:false, no success exit occurs, Storage closes only after successful resource drains, and the concrete owner cleanup cause reaches the runtime logger. External fetch is stubbed to fail and asserted unused.

The direct Host API now exposes the failure through its rejected stop promise; deployed runtime logging is verified separately above.
