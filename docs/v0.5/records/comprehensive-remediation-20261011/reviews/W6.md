## Findings

1. **[P2] Make first lazy encoding atomic after awaiting bytes** — `src/input-media/assets.ts:68`. The `payload.dataUrl ??=` expression reads its left side before awaiting `payload.bytes`. Two first concurrent resolver calls can both see undefined, suspend, then each encode the shared Buffer. An independent bounded probe using the real IncomingAssets class and a temporary 1,000,008-byte file returned equal URLs with `encodings=2`, although final uses/payload maps were empty. Await bytes before the synchronous nullish assignment (or share the encoding promise), and add simultaneous first-resolve assertions for one read/one encoding. The existing concurrent lease test calls resolve sequentially and misses this race.

2. **[P1] Include acquisition in graceful-stop draining** — `src/input-media/service.ts:105` and the acquire wait in prepareForTurn. An accepted preparation can be blocked in readFile before its observation promise enters `observations`. Stop waits assets' download/save/delete jobs and the current observations map, neither of which includes this preparation. It can return with an active lease, allowing storage closure before the preparation resumes and performs cache lookup or persistence. This gap also exists in the baseline lifecycle, but W6 explicitly requires graceful stop to wait in-flight observation work and prevent post-close writes. Track and await complete accepted preparation promises, including acquisition and terminal persistence, and gate the read in a regression. Root independently reproduced early stop resolution in `evidence/w6-review-red.txt`.
