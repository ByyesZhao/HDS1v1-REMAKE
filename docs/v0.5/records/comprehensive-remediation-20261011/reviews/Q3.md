| Requirement | Independent result |
| --- | --- |
| Offline by default | Preparation CLI requires explicit dataset/config/output, branches out before credentials loading or collection without `--online`, and does not create its output in plan mode. Provider construction and signature construction do not call `embed`. Replay adapter only reads the supplied vectors; its implementation has no HTTP call. |
| Collection and resume | The source set uses real `memoryIndexText` and original query text. One text-hash cache spans owner and query entries under an exact signature. Existing dataset/signature mismatches reject before calls; only missing texts are retried. Attempt count is checkpointed before await, success/failure afterward, and sanitized failure history persists after successful resume. The counter is conservatively attempted requests, not proof a interrupted request reached the server. |
| Complete provenance and denominator | Entire-pack validation binds dataset bytes/hash, canonical runtime signature, owner identity/revision/text, query identity/text, dimensions, finite nonzero vectors and duplicate-text consistency. Missing vectors or drift produce incomplete rather than removing queries from scoring. File provenance hashes exact original bytes while unchanged. |
| Real runtime replay and gates | Replay constructs the real index and saves normalized vectors against the original revision/signature. Real SQL eligibility, MemoryRetrieval and ContextBuilder remain in the scoring path. Direct keys, unconditional learned entries, permissions, expiry, vector compatibility, Float32 normalization, default 1500 ms query timeout and RRF60 are retained. Null baseline makes zero provider queries; empty/no-compatible paths also skip. |
| Costs | Collection count, fake-provider calls and replay network requests are distinct. Fake calls increment the real index's legacy remoteRequests; they are not called network cost. An arbitrary external indexFactory correctly reports unknown/null replay network cost. |
| Calibration isolation | Full-vector provenance checks precede scoring; only calibration families and queries are projected into selection evaluation. Holdout labels are not fitted. All 36 complete fact/experience grid combinations plus a real global-null baseline are enumerated, with lexical thresholds fixed at 1. The approved fixed grid is accepted as the finite search design. |
| Candidate eligibility and selection | Both group metrics, overall metrics, eligibility reasons and replay counts are retained. Defined metrics, precision >= 0.95 and no increase in negative-query false hits govern eligibility. Sorting follows F1, precision, fact threshold, experience threshold descending; no eligible result retains global null. |
| Hash-bound, paired, single-use holdout | CLI freezes candidate bytes and hash before a create-only usage claim. Existing candidates require the exact expected hash; semantic candidates additionally bind vector-pack hash/signature. Incomplete preflight fails before candidate/claim. Baseline and candidate share real seed/request/alwaysInclude assertions; the usage claim remains if evaluation/reporting fails, and subsequent use is rejected. This is the documented local workflow, not a global registry against deliberate copying. |
| Q1/Q2 compatibility and deployment boundary | Existing lexical selection, recommendation gates, split isolation, frozen candidate protocol and calibrationFile artifact shape remain compatible in inspected code and fresh synthetic tests. No code path here changes formal defaults or writes the deployment calibration file. |
