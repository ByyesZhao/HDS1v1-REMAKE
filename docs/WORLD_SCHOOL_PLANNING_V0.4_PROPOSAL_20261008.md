# 世界与学校导演每日更新及长期日程方案

日期：2026-10-08。状态：已并入第十一轮审核及接受回应，实施细化／执行计划已生成，源码尚未实施。本次只修改设计文档，不修改源码、运行配置、角色背景或正式数据库。

本方案让学校生活有连续的学期安排、科研任务和周课表，同时保留角色选择参加、缺席、推迟和协调的自由。推荐每天06:00开始世界更新，随后依次检查学校、课题组和周计划，争取07:00前完成。长期计划保存为客观日程；通知发布、角色获知和实际参加分别记录，不能互相替代。

## 1. 已确认要求与本轮建议

用户已确认：每日06:00启动，争取07:00前完成；当前习惯是08:00～09:00起床。学校更新跟在世界更新之后，每天一轮检查一般足够。学期课程、考试、典礼、运动会、学院晚会、假期、班会，以及课题组科研任务、聚餐、游玩可由模型构建。周课表和具体日程应连续、稳定，提前通知角色；参加与否由角色自行决定，学校要求参加也不等于她必然参加。

建议将学校拆为三个可独立配置的模型任务，共用日程存储，而不是三个分别生成完整学校世界的代理。默认沿用用户已有Flash、low配置，后续各任务可以单独改为Pro或调整思考强度。提醒由程序根据已保存的日程生成，不靠学校导演每隔几小时运行一次。

本文说明产品意图；字段、迁移与时序以[实施细化](WORLD_SCHOOL_PLANNING_V0.4_IMPLEMENTATION_20261008.md)为准，实施顺序与验收以[执行计划](WORLD_SCHOOL_PLANNING_V0.4_EXECUTION_PLAN_20261008.md)为准。默认提醒时距及周五生成下周沿用本方案。

## 3. 学校职责如何拆分

### 3.1 选择比较

| 方式 | 优点 | 代价与取舍 |
| --- | --- | --- |
| 一个学校任务包办全部 | 改动少，每日仅一次学校调用 | 学期、科研和具体周日程混在一起，难以分别调模型，容易每日重写大计划。 |
| 三个职责任务、共用日程（推荐） | 目标清晰，计划有固定归属，模型可各自配置；每日仍只一条学校检查链 | 每日最多三次学校调用，需要持久化步骤与统一版本引用。 |
| 三个独立学校代理各有计划 | 单个代理可独立发展 | 重复事件和冲突协调成本高，与现有小型串行架构不相称。 |

任务名及职责如下，字段已在实施细化固定：

| 任务 | 管什么 | 不管什么 |
| --- | --- | --- |
| `world` 世界导演 | 当日公共环境、已有公共事件的延续与变化 | 不决定角色看到新闻后的反应，不生成角色学习成果。 |
| `school_campus` 普通学校导演 | 学期起止、课程清单与重复时段、考试／考核、校院活动、假期、班会及校园NPC机会 | 不安排角色个人选择，不修改课题组内部任务。 |
| `school_group` 课题组学校导演 | 导师要求、科研任务与阶段节点、组会、聚餐、集体游玩、同门邀请及必要调整 | 不实际执行科研，不把布置任务写成完成任务，不改校园课表。 |
| `school_week` 周计划学校导演 | 将上游计划落实为本周及下一周的具体日期、课表、事件和通知方案，检查冲突与缺漏 | 不每周另造课程，不自行改上游考试／导师要求，不替角色决定参加或答应邀请。 |

三个学校步骤每天都可调用，但有完整计划且无变化时，允许返回空变更。每日检查不是每日新增任务或换一套课表；课程为空、科研为主的周也合法。

校园与课题组持有自己上游计划的写权限并提供通知策略；周任务是实例／通知候选的唯一模型展开者，引用上游条目和版本；程序唯一负责稳定身份、保存、发布及失效。周任务发现冲突可以报告、保留客观冲突或请求所属任务下次协调，不能偷偷把学校时间和导师截止改成角色方便的时间。角色如何取舍仍由个人导演决定。

## 4. 每日批次与让位规则

### 4.1 固定启动，不按上次完成时间漂移

故事时区使用已有`Asia/Shanghai`配置。固定单一配置`environmentDailyAt='06:00'`；旧worldTimes／schoolTimes只作加载兼容，不再驱动定时，旧nextWorldAt／nextSchoolAt在升级时置null。每日06:00创建当天批次，按以下顺序推进：

```text
world → school_campus → school_group → school_week
```

每步成功提交后才能选择下一步，后一步读取已提交结果。一个日期成功步骤不重复运行；阶段、结果和批次日期保存到数据库，重启从未完成步骤继续。起床不是这个批次的前置条件，角色睡着时可以更新客观环境。

07:00是期望完成时刻，不是丢弃任务或强行成功的截止。模型等待、格式修补和前台让位都可能造成延迟；不能保证网络请求必然在一小时内结束。迟到批次继续在可用空档完成，不设“等学校链全部完成才可起床或聊天”的门禁；起床／聊天轮在下一个串行选择点使用当前已提交环境。单次已开始请求的等待限制见下一节。

### 4.2 每一步之间检查前台

沿用当前单故事串行执行方式，明确不将四次模型调用放进一个不可让位的大回合：

1. 先完成既有未完成故事／发送／后处理，再选新工作。
2. 每个环境步骤完成后，实际让出事件循环，再重扫消息合批、共同推进、具体预约、可读学校通知、起床等前台原因。
3. 有可运行前台时先运行前台；没有时继续当天批次下一步。
4. 无前台时，待办环境步骤仍在空闲自主轮之前；记忆维护按既有让位规则处理，不与环境一次锁住整条晨间链。

普通消息已经进入15秒openBatch但尚未到合批时刻时，也暂不新开环境步骤，等待合批后重扫；共同消息则沿用既有60秒窗口资格，不把整场共同活动当成环境禁区。这样不在已经收到普通消息的合批间隙抢先开启长环境请求。

**实际限制：已开始的一次环境模型请求仍占用当前串行故事槽。** 新消息立即落库，但故事响应可能等该请求完成；“步骤之间让位”不能称为“正在请求时完全不影响聊天”。本轮推荐保留这一已实现的执行方式，不新增并发环境执行器。若后续实测要求连单次环境请求也不占前台，再单独细化类似记忆维护的异步准备／短事务发布机制。

### 4.3 首次运行、跨日与失败

新库首先建立当前学期、当前研究安排和当前周，而不是生成已经错过的整个学期经历；首次初始化允许在启动后的空档执行一次建档批次，随后固定每日06:00检查。

离线多天后只恢复必要未完成步骤并检查当前日期，不按漏掉的天数连续补跑全部批次。不对历史安排伪造“已经通知／已经参加”。若旧步骤未产生提交且已明显过时，显式标为被当前日期检查替代；已提交的部分保留，当前检查延续它们。

第一阶段即隔离环境模型失败：批次步骤独立持久化，不创建阻挡普通故事的unfinishedTurn。模型请求／格式修补失败保存retryAt和lastError，默认5分钟后按同样前台让位资格重试，不全局暂停、不跳过依赖、不向QQ重复报错；等待retry不抑制到期自主／维护。数据库提交错误不笼统当模型重试，普通前台失败及人工暂停保留既有语义。执行仍串行，不新增后台并发服务或正式模型超时。

旧done=false环境turn在停服备份升级事务中显式标为superseded、记录closedAt和replacementBatchId，保留未成功含义及历史结果，不应用旧未提交结果；所有恢复／诊断统一排除已终结尝试。普通／共同未完成轮继续恢复，paused不自动清除。环境规划有独立版本门禁，旧配置及旧格式临时库均须验收。

## 5. 学期计划与课题组计划

### 5.1 学期计划

一个学期生成一份持续有效的计划。包括学期日期、角色本学期修读或补修的课程、每门课的大致目标／考核方式／重复时间、考试或报告节点，以及典礼、运动会、学院活动、假期、班会等粗粒度事项。并非所有列举事项每学期都必须出现。

角色是联合培养在读研究生，课程数量和研究比重要符合既有背景，不按本科生固定满课安排。允许本学期没有常规课程，主要是组会、讲座、研究和必要培养环节；不要为了“有课表”强行编满每日。

具体排课时段一旦确定，跨周复用。缺确切时刻的事项保存为暂定日期／时间范围，不能伪装成已确定通知；接近日期后由归属导演明确时刻，再落实提醒。学期中允许有依据的调课、改期和取消，以原条目ID更新并记录原因。

### 5.2 课题组计划

保存当前研究阶段与导师下发的任务：任务说明、负责人／相关NPC、下发时刻、截止或暂定期限、阶段节点、预期交付形式，以及固定组会、聚餐和游玩安排。社会活动可以是确定的集体安排，也可以只是邀请，不能自动写成角色已经答应。

导师任务可以是阅读论文、整理数据、尝试方法、准备组会汇报、补实验、修改稿件等情境内容。**它们是模拟生活素材，不触发真实实验、代码运行、论文生成或向导师发送消息。** 搜索只是导演构建合理背景的工具，研究结果仍来自模拟故事。

研究任务采用简单的“开放／撤回／关闭”生命周期和带来源的进展记录。下发导演负责要求、期限及待发生的导师反馈；只有主叙事已提交的experienceId／turnId及实际时刻才能支持进展或完成结果。导师反馈先由主叙事实现为可感知经历，不另造脱离经历的反馈ID。个人导演提出“今晚试一种方法”是意图，不是任务进展；周计划排出“完成实验”也不代表实验已成功。

主叙事结合既有个人意图、已过去时间和客观条件生成做事过程、困难、部分结果或成功／失败。不能在未过去的时间一次完成数日工作，不为追赶导师期限保证成功。后续组导演读取相关研究进展与汇报经历，继续安排反馈或调整任务。

### 5.3 学校事实与虚构权限

本轮用户授权学校导演构建未来学校生活，补足原背景“无证据不擅自补具体课表”的空白。生成并保存的模拟计划可以成为后续故事依据，但不能反称它是某大学真实官方课表、真实导师通知或真实研究结果。

既有姓名、身份、学院、年级、研究方向等明确背景优先；未经用户修订不改写。现实校历、法定假期和真实制度若作为现实事实引用，需要可核验来源；无来源时不冒称核验，可使用明确标为虚构的校园安排／暂定假期。网页搜索未接入真实provider时仍按现有禁伪联网规则处理。

## 6. 周课表和日程实例

每周以本地周一为周起点。第一次初始化建立当前周；常规建议在前一周的周五晨间检查生成下一周，周一确认本周。保存当前周及下一周的具体实例，不逐日调用模型重新猜课表，也不一次展开整个学期的每节课。

周计划读取已保存的课程重复规则、学期节点、课题组节点、取消／改期记录和必要的现实日历依据。输出两类内容：

- **客观固定事项**：星期、时间、地点、课程／组会／班会／考试／集体活动，及对应上游来源条目。
- **可选安排或空档建议**：讲座、聚餐邀请、科研空档等，可供个人导演决定采用；不能变成角色已经确定的私人计划。

课程实例以“来源条目＋稳定时段键＋本地周起点”建立稳定身份，同一节课跨日检查不重复创建，改期不因换日期而复制；科研期限和一次性活动以来源条目关联，改期更新同一未来实例。周计划不得给导师下发或校园通知再生成一份互不关联的复制品。

本周／下一周是常规展开范围，远期事项的当前下发、改期、取消通知不受此窗口阻挡；下月期限今天下发，今天仍要通知要求。必要远期一次性实例可保留，不因此展开全学期每节课。

多个真实客观安排可以冲突，程序不拒绝所有时间重叠。周导演标明冲突，个人导演可选择参加哪一个、缺席、请假或联系协调。真实共同预约也不自动取消学校活动；共同活动期间通过合法共同轮协调，保留两者的原始安排。

周中无变化返回空变更；发现改期／取消／新任务时只增量更新受影响实例和通知。已经被角色实际参加的部分保留历史，不能因周计划更新改写过往经历。

## 7. 通知、已读和角色选择

### 7.1 定时提醒独立于学校每日调用

一次学校更新可以安排未来通知。通知到期由程序让它变成“已发布、可读”，无需再次唤起学校模型。建议模板：

| 事项 | 默认通知方式 |
| --- | --- |
| 周课表 | 周计划发布后提供一次本周／下周课表通知；日常每节课不重复前一天通知。 |
| 常规课程／固定组会 | 按已知课表，可在开始前约1小时提供临近提醒；学校机构通知与角色个人提醒在来源类型上区分。 |
| 一次性班会、考试、集体活动 | 默认提前1个本地日及开始前2小时各一次，满足用户提出的“两次通知”例子。 |
| 新下发科研任务 | 下发时可读通知；临近明确期限时提醒，长期开放任务不每日催促。 |
| 临时改期／取消 | 变更发布时通知；使旧时刻尚未读取的提醒失效，必要时生成新时刻提醒。 |

一天两次检查同一事件不新造两套提醒。通知身份关联来源／实例、公开内容版本和提醒类型；已读通知保留，不被更新覆盖。上游改期／取消提交时立即使旧待发／未读通知失效并标记实例待展开，周任务之后填新提醒；仅内部备注改变不重发全部通知。如果日程第一次建档时已过某个提醒时刻，只发布一条当前仍有意义的通知，不补发多条历史“你本应知道”提醒。

模型可给特定事件选择不提醒或补充合理通知方案，程序根据结构化时间展开；不增加每项强制两次的硬规则。没有确切开始时间时只发暂定安排／确认通知，不猜“前2小时”的时刻。

### 7.2 发布不等于已读

通知用独立学校通知记录保存，不写用户incoming，不自动发给用户QQ，也不套用双方`【动作：】`或`【推进】`控制。核心过程是：

```text
日程确定 → 通知到期发布 → 角色有条件接收 → 故事实现获知 → 段B提交已读 → 自由决定
```

睡眠、洗澡等不可读状态只保存待看通知，不唤醒她、不强制中断。可读时，通知可以与已有聊天／预约／自主故事合并；没有现成故事时允许选择school_notification触发轮，先主叙事补齐生活，实际获知后用个人生活导演决定反应。纯学校通知不视为用户发言，contactEligible=false，不获得自主联系用户抽样资格；角色可以只在心里调整计划，不必向用户说出来。可读通知优先自主，不可读通知不永久压住正常生活。

已知不可读活动结束时可安排一次统一检查；结束未知则留到已有起床／自主／其他前台触发，不建立高频轮询。角色拒看后留待下次合法故事，不立即反复开通知轮。共同活动期间通知待下一合法共同节点交付；不单独绕过60秒窗口或生成额外共同轮，不作为双方真实新输入关闭代写分支，也不因普通学校事项直接开始第二场活动。

通知阅读标记仅在对应故事段B成功提交时保存；修补、暂停、恢复不重复阅读计数。选轮后到达的新通知留待下一轮，不追加到已冻结模型输入。

实际运行角色主叙事的学校通知轮属于前台故事，成功结束后按已有规则重新安排150～210分钟空闲自主间隔。通知仅发布、睡眠暂存、客观环境更新不重排自主时间。

### 7.3 两阶段的知识输入

主叙事取得与`[from,at]`和当前场景有关的客观日程、已发布可感知通知及旧已读事实。它可以描述通知发布、角色查看或现场获知，但没有阅读条件时不能把消息写成已经看到；晚生成的安排不能倒插成过去已经获知的历史。

个人导演取得此前已知的计划／通知**版本快照**、主叙事本轮实际实现的获知内容和对应经历，不能凭旧已读ID直接读取客观最新值。**不再直接取得所有尚未发布、未读的学校事件。** 秘密的导师计划、未发邀请和未来临时通知不能从events、关联引用、lookup、表达或记忆入口泄露；个人检索query不加入全部客观学校描述。

relatedEventIds及主叙事eventIds白名单不是已读证据。主叙事以结构化学校观察引用通知／现场事件及对应experienceIndex，程序验证发布／版本／条件，再沿用该经历ID保存获知。主叙事仍拥有相关客观范围，其experiences只能写角色实际感知事实；不把隐藏安排当角色亲历。自然语言是否泄漏仍靠提示词和真实多轮验收，程序不冒充语义审核。

已读计划允许进入她对未来的理解和决策上下文，不必每天重复通知才能记得一门课；已读不再作为新来源交付，已知内容可按需复用。临近提醒是再次提示，不代表原安排第一次被知道。周课表知晓也不使尚未发布的临时变更自动已知。明确查询远期／历史安排时可按请求取得相关已知信息，不把常规周窗口当硬容量限制。

学校标记“要求参加／需提交材料”只是客观要求。个人导演可参加、缺席、迟到、请假、改个人工作顺序或拒绝邀请；主叙事再实现实际过程和可能后果。通知本身不自动建立共同活动或替用户接受邀约。

## 8. 存储、记忆与时间范围

使用现有SQLite／JSON存储扩展以下逻辑记录，具体名称和字段已在实施细化固定：

| 记录 | 用途 |
| --- | --- |
| 每日环境批次 | 本地日期、独立步骤、完成／失败／重试与替代状态；不挂前台turn门禁。 |
| 学期／课题组计划 | 有稳定ID和版本的客观计划，日期范围、归属、条目、来源及取消记录。 |
| 学校日程实例 | 具体起止、地点、来源条目、确定／暂定、角色参加要求、改期记录；可与现有school事件保持关联。 |
| 学校通知 | 关联实例／版本、发布时刻、渠道类型、内容、待发／可读／已读／失效状态、实际已读turn。 |
| 角色学校知识 | 实际获知版本快照、时刻、experienceId和turnId；不同于客观最新计划。 |
| 研究进展 | 关联任务、已经实现的经历／反馈来源、发生时刻和摘要；不保存真实科研执行产物。 |
| 周计划检查记录 | 周起点、已覆盖范围、引用的上游版本、最近检查与变化原因。 |

这些计划是结构化未来安排，**不受长期记忆90天期限支配，也不依赖唤醒次数保住一个学期**。学期结束、任务关闭和事项到期后归档，保留历史，未来故事只选当前／相关记录；不新增人为字符或token预算，不默认把全部学期实例塞进上下文。

通知实际阅读及活动实际参加可通过主叙事经历、角色感受等已有合法来源进入记忆V0.3。未来课表／科研要求放在“安排与意图”上下文，不能作为已经参加／已经研究完成的来源；通知已读只能证明获知安排。阅读事实可以记成“收到下周班会通知”，不能记成“参加了班会”。

学校客观计划先做时间、归属与身份筛选；角色计划上下文还要限制为已知信息。暂不新增一套学校Embedding索引，既有亲历和查阅记忆继续使用当前检索。未来若需按研究任务查找大量历史计划，可针对计划记录扩展检索，但须同样执行已知范围过滤。

## 9. 模型与工具配置

保留world，将原school职责拆为school_campus/school_group/school_week。加载时在严格Schema解析前仅用旧school补齐缺失的新项，各自复制；显式新项优先、错误不回退，新项齐全可无旧school。加载不自动改配置／密钥。默认均Flash、low，不能借本次改造把记忆整理或表情包识别的high改掉。

每个新任务沿用自己环境步骤的网页会话：成功读取20次、失败40次，细节查询续调用、格式修补及恢复重试沿用对应任务会话和模型。不同学校任务不共享一个额度池。新增环境所有者不算角色个人网页阅读；school_*继续环境currentOnly检索权限。实际搜索provider尚未选择，此方案不顺带启用联网服务。

学校模型只查询与职责相关的设定和已保存计划：校园任务需要学籍／学院／培养背景，课题组需要导师／师姐／研究方向等明确事实，周任务需要上游计划和已确认预约的相关时段。不得因为旧正则漏了导师细节而凭空另造导师，也不将完整私聊发送给环境导演。

## 10. 一条班会与一项科研任务如何流转

以下时间和事项仅用于说明模拟流程，不是实际学校日程：

周五晨间校园导演延续学期计划，确定下周三15:00班会；周导演把它落实为同一条周实例，程序保存周二15:00和周三13:00两次提醒。周二提醒发布时她在洗澡，通知留待看；洗澡结束后的合法故事中主叙事实现她查看通知，个人导演可以觉得麻烦但决定参加，也可以打算不去。周三再次提醒时若正共同活动，等下一合法共同节点交付，她再协调是否结束共同活动赶去。无论哪种选择，通知不会直接把当前场景改成班会教室。

课题组导演下发“下周组会前比较两种方法”的任务。角色获知后个人导演决定今晚先看资料，主叙事在下一次唤起补出实际阅读过程和遇到的问题。第二天组导演读取已有进展，可安排导师反馈或保持任务不变；周导演提供截止和组会日程。没有实际研究经历时，任何导演都不能因“已排了实验时间”就写出实验完成。

## 11. 后续实施划分及验收重点

实施顺序已在执行计划固定为八项，沿用原项目逐任务记录与本地Git方式：

1. 配置解析前兼容、共享类型、计划归属、来源、身份和版本存储；不把旧active描述认作已读。
2. 06:00每日批次、步骤让位、失败隔离和恢复；固定单次请求占用前台的实际限制。
3. 三个独立学校模型、增量合同、职责输入和独立网页会话。
4. 周实例、通知稳定身份、定时发布与变更／取消传播。
5. 通知故事、个人已知版本、观察及研究来源、段B原子提交。
6. 旧库只读检查／停止备份升级、旧环境轮终态及正式入口版本门禁。
7. 样例、离线集成、实际行为文档同步与过程记录。
8. 已授权范围的隔离真实模型跨日／跨周验收，记录实际通知获知、自由选择和模拟研究，不连接QQ或执行真实研究。

最低验收包括：06:00世界后学校，旧步骤恢复且不重复；步骤间新聊天优先；周计划无变化不重建；周中改期不复制事件且旧提醒失效；睡眠／洗澡通知只暂存；已知课表可继续使用而未读临时变更不泄露；强制班会仍可拒绝；科研意图和排程不自动变成果；通知轮不自动获得主动联系资格；共同活动不被提醒绕过窗口；实际前台阅读后自主周期按现规则重排；来源和恢复不重复。
