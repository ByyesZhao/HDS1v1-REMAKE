## 1. 用户已决定的事项

1. 超出实际接口容量时：**不自动移除历史，保留报错处理**。平时仍默认无人工字数／条数预算，不改数据库正文。
2. 网页能力：开放搜索及后续读取，**所有模型阶段均可按需申请**。
3. 各逻辑模型任务独立success／failure：最多成功20次，失败40次；同任务的搜索续调用、补查及格式修补不重置。世界、个人等不同任务不共享剩余额度。
4. 实施接入：**先保留可替换适配器，稍后选搜索服务**；当前不要求用户决定具体厂商或提交密钥。
5. 本轮仍不修改代码、启动服务或执行真实搜索。

## 2. 网页12000截断：补明确步骤，纠正“自相矛盾”分类

[src/index.ts](../src/index.ts)第77行确实有 `.slice(0, 12000)`。但两份文档明确标为尚未编码的V0.3，计划任务7已列src/index.ts并要求“>12000字符默认保留尾部”的可见测试。现在源码仍是V0.2，不与未来设计矛盾，也不表示这个测试已经通过。

采纳“把要改的代码入口写清楚”的建议。后续实施步骤应明确：

> 将现有getWebMaterials的固定URL批量抓取移交共享搜索模块；移除默认 `.slice(0, 12000)`，正文不按固定字符数截断。搜索和直接读页沿用同阶段session，以成功20／失败40限制读取尝试，而非按字数额度筛正文。

原有参数实际上是字符上限，并不是精确token上限。新读取配额控制操作数量，无法改变供应商技术容量，也不要求成功读取的所有HTML都直接拼入模型。正文去除导航／脚本等无关内容，保留与检索主题相关的材料。

原计划的webMaterialCharactersLimit可在下一次衔接时撤去，以独立WebSearchConfig承接；无须把网页配置塞进记忆ContextLimits。

## 3. 容量兜底：用户已选择报错，不自动裁剪

### 3.1 默认不限的定义并不含糊

细化§6.3已明确“未配置或显式null均表示对应人为限制关闭”。对本项目来说，null与默认不限之间没有第二种读法；当然，接口真实容量不会因此消失。

“取消条数上限”也不等于“把全部记忆发送”。应依次做权限／日期／状态筛选、相关性判定、去重、排序，再提供入选资料。词法／向量在库中扫描的规模和最终模型上下文的规模是两件事。

近期原文只30条；按需经历先相关检索；核心、当前状态、本轮来源及经过判断的alwaysInclude稳定认识单独提供。总请求还包括提示、合同及其他材料，因此不能保证永不超限。但本轮没有实测数据支持“连续几个月后很容易因为几万字符就超限”的判断，不应据此恢复默认固定预算。

### 3.2 已给出明确选择

用户已明确选择“不自动移除，保留报错处理”，所以不采纳REVIEW5§2的技术容量自动删条方案。也不增设通用token估计上限或按预测容量提前删条。

接口若确实报容量错误：

- 前台故事沿既有异常路径处理，保留未完成轮、记录错误并暂停，等待排查／用户恢复；不删历史后自动重发。
- 后台维护沿后台失败规则记录待办，不因此暂停正常故事。
- 原始记录不变；这个规则不覆盖网络超时、格式修补等已有规则。

应增加一次明确容量错误的离线模拟验收：HTTP返回容量错误后没有自动构造缩小输入的第二次请求，未修改记忆，前台／后台错误分别走对应路径。正常相关候选输入仍默认不限。

## 4. RRF之前的相关性：采纳补齐规则

现有[src/memory/context.ts](../src/memory/context.ts)按中文二元组、英文词／数字拆词，词法分数只要求大于0。若直接取消Top K并沿用这个宽泛条件，确实可能纳入大量弱匹配。这是需要改变的普通检索逻辑。

建议下一次文档衔接明确：

1. key／明确别名的精确匹配仍是独立入口。
2. 词法路先剔除通用叙事词的弱命中，按有效词命中覆盖度判定相关；短查询不能机械要求至少多个词，否则一个明确姓名／事实key也会被漏掉。
3. 词法相关性规则同样用事实／经历正反例标定并验证，不能把“score>0”直接当合格。阈值属于相关性，不是固定条数／字数预算。
4. 向量路保持标定门槛；未标定时semantic-only不开启。
5. RRF60只对两路已经合格的候选融合排序，不替所有非零命中背书，也不恢复固定24／12／8配额。

这个改动与用户“先相关检索再投喂”的意图一致，不需要用户拍一个随机最低命中词数。具体阈值应由标注样本决定。

成本应通过10,000条及三／六个月样本测量；先做SQL有效状态／期限筛选，使用已归一化向量。没有运行基准前，不断言全量排序已经不可用，也不为此添加外部向量数据库。

## 6. 新共享搜索模块与阶段独立额度

有必要单独设计模块，理由是全阶段搜索需要共同处理工具续调用、来源、额度、恢复和可见性，不能在每个导演函数里各写一套HTTP循环。

模块实现共享，各次runModel的session独立。成功和失败独立计数，操作前检查success<20且failures<40；到任一上限即停止。18成功＋3失败仍可继续，8成功＋40失败必须停止。阶段可以达到需要后提前结束，不必为凑20页继续查。

搜索后读链接与直接webRead也用本session；改关键词／格式修补不能重新拿20／40。仅看搜索结果列表不算成功读取正文。具体计数口径、接口及来源规则见新设计文件。

“所有阶段可搜索”不扩大角色经历或正式状态修改权限：记忆整理仍需真实本轮来源，网页不能单独证明角色亲历；后台压缩仍只基于业务快照，外部材料另外登记。后台搜索仍占原准备槽，不占前台故事槽。

现有代码没有开放搜索引擎，只有配置URL读取。用户选择先设计可替换WebSearchProvider，可离线验证，不冒充已经接好真实服务。后续正式联网前选择实际适配器及必要本地配置即可。
